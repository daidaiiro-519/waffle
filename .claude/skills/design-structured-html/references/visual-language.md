# 視覚言語

## 設計原則

視覚表現は意味の階層を補助する。装飾の種類を増やすのではなく、同じ意味に同じ形を繰り返す。

## デザイントークン

CSS変数を使い、少なくとも次を定義する。

```css
:root {
  --bg: #f5f8f7;
  --surface: #ffffff;
  --surface-muted: #edf4f2;
  --text: #14211e;
  --muted: #5d716a;
  --line: #d5e2de;
  --primary: #087861;
  --secondary: #176da7;
  --success: #16845b;
  --caution: #b65b17;
  --risk: #a53b42;
  --radius: 18px;
  --shadow: 0 10px 35px rgba(20, 55, 44, .08);
}
```

色値は内容や既存デザインに合わせて変更できる。役割名は維持する。

## 色の意味

- `primary`: 文書の主軸、現在位置、主要アクション
- `secondary`: 比較対象、別視点、補助系列
- `success`: 成立、完了、有効
- `caution`: 注意、要確認、人間判断
- `risk`: 失敗、重大制約、無効
- `muted`: 背景、補足、非主要情報

研究固有の「Baselineは青」のような対応を既定にしない。文書ごとに色の意味を決め、途中で変更しない。色とラベルを必ず併用する。

## タイポグラフィ

- 本文は日本語で読みやすいシステムフォントを優先する。
- 本文行長は概ね45〜80文字に抑える。
- 本文の行高は1.6〜1.8を基準にする。
- 見出し階層はサイズだけでなく余白でも示す。
- コード、ID、数式だけ等幅フォントを使う。
- 大文字化や字間拡張は短いKicker・Eyebrowに限定する。

## 密度と余白

- セクション間隔 > カード間隔 > 段落間隔の順に大きくする。
- 1画面に強いアクセントを複数競合させない。
- カードの角丸、境界線、影は少数の値へ統一する。
- 文章が長いカードでは、装飾を増やすより内部見出しやリストで分節する。

## レイアウト

- 長文では本文最大幅を設け、必要なら左に目次を置く。
- 2〜3列カードは同粒度の項目だけに使う。
- モバイルでは原則1列へ落とす。
- 表とコードはコンテナ内で横スクロール可能にする。
- 固定・sticky要素が本文を覆わないよう`scroll-padding-top`を設定する。

## Hero

Heroには文書の方向づけだけを置く。

- Eyebrow: 文書種別または状態
- `h1`: 読者が理解すべき主題
- Lead: 一文から二文の要旨
- Chip/Stat: 本当に重要な規模・状態だけ

背景のグラデーションや装飾円は使用できるが、コントラストと印刷時の可読性を確保する。

## レスポンシブ・ダーク・印刷

- 1100px前後でサイド目次をモバイルナビへ切り替える。
- 700px前後で複数列、フェーズ、比較パネルを1列へする。
- `prefers-color-scheme`と`data-theme`の両方に対応できるようにする。
- 印刷ではsticky、ボタン、進捗、影、過度な背景色を除く。
- カード、表、フェーズ、コードを可能な範囲で改ページ途中に分断しない。

## インタラクション

許容される既定操作は、目次、現在位置、テーマ切替、コピー、`details`。アニメーションは短く、`prefers-reduced-motion`を尊重する。操作できる要素には`button`や`a`を使い、`div`クリックを避ける。

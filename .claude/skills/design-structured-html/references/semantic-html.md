# 人間とAIが読めるHTML

## 文書構造

- `<!doctype html>`、`html lang`、UTF-8、viewport、具体的な`title`を設定する。
- `header`、`nav`、`main`、`section`、`footer`を用途どおり使う。
- `h1`は文書主題に一つ置き、見出しレベルを飛ばさない。
- 各主要`section`に一意で安定した`id`を付ける。
- 目次リンクのフラグメントを実在するIDへ結びつける。

## 関係を明示する

- 表には`caption`、列見出し、`scope`を付ける。
- 用語と定義には`dl`、`dt`、`dd`を使う。
- 手順には順序付きリストまたは明示的なフェーズ番号を使う。
- 引用と出典、コードと説明、警告と対象を近接させる。
- 「これ」「上記」だけに依存せず、対象名や安定IDを併記する。
- 数値には単位、分母、期間、尺度を付ける。

## AI可読性

- セクション冒頭に、その節の目的または要点を短く置く。
- 同じ概念には同じ語を使い、装飾用の言い換えで識別を崩さない。
- カード種別ごとにラベル順を固定する。
- IDは表示順ではなく意味に基づける。例: `measurement-method`、`risk-validity`。
- 重要な関係を視覚的位置だけに依存させず、「目的」「入力」「出力」などのラベルで記述する。
- 重要本文をCanvas、画像、CSS疑似要素、動的取得の中だけに置かない。
- JavaScript無効時にも本文と基本ナビゲーションを読めるようにする。

## アクセシビリティ

- 画像には目的に合う`alt`を付ける。装飾画像は空の`alt`にする。
- ボタンには可視ラベルまたは`aria-label`を付け、`type="button"`を指定する。
- 現在位置には`aria-current`を使用できる。
- テーマ切替後も十分なコントラストを保つ。
- フォーカス表示を消さない。
- 色だけで状態を表さない。
- 動きを減らす設定を尊重する。

## 出典と確度

出典のある主張は、著者・組織、年、タイトル、URLまたは識別子を可能な範囲で示す。直接確認済み、二次情報、推論、仮説をラベルで区別する。リンクテキストは「こちら」ではなく出典名にする。

## 構造化データ

JSONやスキーマを提示する場合は、人間向けの説明を先に置く。構造化データだけを意味の正本にする場合でも、フィールド名、型、必須性、単位、列挙値を本文または表で説明する。HTML内のJSON-LDは検索や外部連携の明確な用途がある場合だけ追加する。

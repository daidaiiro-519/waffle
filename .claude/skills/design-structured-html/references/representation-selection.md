# 表現形式の選択

表現は見た目ではなく、読者が行う認知課題に合わせて選ぶ。

| 読者の課題 | 第一候補 | 適する条件 | 避けること |
|---|---|---|---|
| 正確な値・属性の照合 | 表 | 列の意味と対象の粒度が揃う | 値をグラフだけにする |
| 2〜4案の比較 | 比較表・横並びパネル | 同一評価軸で比較できる | 各案を離れた節に置く |
| 時間順・処理順 | 番号付きフェーズ・フロー | 順序や分岐が理解に必要 | 単純な2段階を巨大な図にする |
| 状態と遷移 | 状態表・状態図 | 開始条件と遷移条件がある | 状態名だけのカード列 |
| 独立した概念群 | カードグリッド | 各項目が同粒度で自己完結する | 長文を小箱へ詰め込む |
| 階層・所有・包含 | ツリー・入れ子リスト | 親子関係が中心 | 横一列のフローで代用する |
| 因果・依存関係 | 因果図・依存図 | 3要素以上の影響関係がある | 因果を単なる順序として描く |
| 少数の重要数値 | Stat | 文脈を代表する値が1〜6個 | 数字を飾るだけで置く |
| 重要な境界・警告 | Callout | 本文から視覚的に区別すべき | 色だけで深刻度を示す |
| 長い補足 | `details` | 読まなくても主線が理解できる | 結論や重大警告を隠す |
| コード・JSON・コマンド | `pre` + `code` | 空白・記号・コピーが重要 | 通常段落へ混ぜる |
| 典拠・文献 | 参照カード・文献表 | 著者、年、知見、適用、限界を整理 | URLだけを並べる |
| 短い定義対応 | Definition list | 用語と説明が一対一 | 3列以上の関係を無理に表す |

## カードの使い分け

- **Concept card**: 名称、短い定義、役割、関係
- **Evidence card**: 主張、根拠、適用範囲、限界、出典
- **Decision card**: 判断、条件、理由、リスク
- **Procedure card**: 入力、操作、出力、完了条件
- **Variable card**: 定義、尺度、取得方法、用途、根拠

カード内のラベル順を同じ種類のカードで揃える。情報量が多い場合は、カードを増やす前に表または詳細節が適切か再判断する。

## フローの制約

- 横一列は原則5ノード以下にする。
- 6ノード以上は複数フェーズ、折返し、縦方向のいずれかへ変える。
- 矢印だけに意味を持たせず、開始条件、操作、成果物を文字で示す。
- 分岐がある場合は条件名を明示する。

## 表の制約

- 1行目で列の意味が分かる見出しを付ける。
- 比較表では行または列のどちらか一方に評価軸を統一する。
- 長い文章を多数の狭い列へ分割しない。
- モバイルでは横スクロール可能なラッパーに入れる。
- 行の強調は色に加えてラベルを使う。

## 視覚化を使わない判断

文章2〜4文または小さな表で関係が十分理解できる場合は、図を追加しない。図を作る目的を一文で説明できない場合も使用しない。

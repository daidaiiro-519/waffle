# 情報アーキテクチャ

## 目的

読者が全文を順番に読まなくても、重要度、関係、次の行動を把握できる構造を作る。

## 基本の意味階層

1. **Orientation** — 文書の対象、目的、状態
2. **Conclusion** — 中心結論、判断、要約
3. **Context** — 前提、範囲、用語、入力
4. **Structure** — 比較、構成要素、関係
5. **Operation** — 手順、責任、取得方法
6. **Evidence** — 根拠、データ、出典
7. **Qualification** — 例外、限界、未確定事項
8. **Action** — 次の判断、作業、チェックリスト

すべてを必須にしない。読者の課題に必要な意味階層だけ選ぶ。

## 文書タイプ別の推奨骨格

### 調査・研究整理

結論 → 問いと範囲 → 主要テーマ → 先行知見・根拠 → 統合 → ギャップ → 方法 → 限界 → 参考文献

### 仕様・設計

目的 → 境界 → 用語 → ユースケース → ルール → 状態・フロー → 入出力 → 例外 → 検証条件 → 未決事項

### 比較・意思決定

推奨判断 → 比較条件 → 評価軸 → 横並び比較 → トレードオフ → リスク → 選択条件 → 次の行動

### 手順・プロトコル

目的 → 前提 → 入力 → 全体フロー → フェーズ別手順 → 取得データ → 完了条件 → 例外処理 → 品質確認

### 学習ノート

何を判断する知識か → 結論 → 概念と役割 → できること／できないこと → 比較 → 誤解 → 判断パターン → 復習

## 分節化の規則

- 一つのセクションは一つの主要質問へ答える。
- 一つのカードは一つの概念、主張、対象を扱う。
- 見出し直後に、そのセクションを読む目的を1〜3文で置く。
- 長い列挙は、カテゴリ分けできるならカテゴリを先に示す。
- 例外は該当ルールの近くに置き、文末の「その他」へ隔離しない。
- 主張と根拠を離しすぎない。離す場合は安定した参照IDで結ぶ。
- 用語の同義語を無制御に混ぜない。最初に採用語を定義する。

## 段階的開示

最初の画面では次だけを優先する。

- 文書名
- 一文の目的
- 中心結論または現在地
- 重要な規模・状態を示す少数の指標
- 主要セクションへの入口

詳細、証拠、長いコード、全参考文献は後段へ置く。ただし、結論の条件や重大な警告は隠さない。

## 情報局所性

次の組は原則として同じセクション、カード、表の行に置く。

- 用語 — 定義 — 具体例
- 主張 — 根拠 — 確度
- 変数 — 目的 — 取得方法 — 分析方法
- 手順 — 入力 — 出力 — 完了条件
- 判断 — 適用条件 — 非適用条件
- リスク — 原因 — 検出 — 対応

## 冗長性の扱い

意味の正本は一つに保つ。冒頭要約や比較表で再掲する場合は、詳細の複製ではなくナビゲーション用の短い要約にする。数値、ルール、条件を複数箇所へ直接複製する必要がある場合は、変更時に同期できる仕組みか参照を用意する。

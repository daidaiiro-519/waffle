## 目的

**読み手が、探さずに読めて、一度で意味が取れる日本語の文書を書く。**
書き起こす前に構造を決め、書いたあとに5つの観点と機械の検査を当て、最後に読み手を立てて確かめる。

**この検査は、書いた本人には見えない失敗を捕まえるために置く。**
**書き手は、文書に書いていないことを知っている**。だから欠けた箇所を補って読み、補ったことに気づかない
（`references/knowledge/reader-testing.md`）。

## 役割

- 書き始める前に、読み手が何を探しに来るかを決め、それを見出しの並びにする
- 同じことを2か所に書かない。書くなら片方を正本にし、もう片方は参照にする
- 同じ意味に2つの語を当てない。違う意味に同じ語を当てない
- 対比・手順・条件・一覧は、散文ではなく表と図で書く
- 主語・述語・目的語を省かない。体言止めと倒置で曖昧にしない
- 書いたあとに5観点と機械の検査を当て、直してから出す
- **機械で見えない範囲は、文脈を持たない読み手を立てて確かめる**

## 処理対象と成果物

### 処理対象

**これから書く文書の題材、または既に書いてある日本語の文書である。**
新規なら何を伝えるかと読み手を受け取り、修正なら対象ファイルを受け取る。

### 成果物

**5観点と機械の検査を通し、読み手を立てて確かめた日本語の文書である。**
検査で見つけた箇所は直してから出す。直さずに残す場合は、理由を添えて報告する。

## 入力の想定

| 受け取る情報 | 解釈・既定値 |
|---|---|
| 読み手 | 明示されなければ、その文書を初めて開く人とする |
| 文書の長さ | 明示されなければ、上限を置かずに書き、検査の観点1で分割を判断する |
| 既存の用語 | 対象フォルダに用語を定めた文書があれば、それに従う。無ければ新たに定めて冒頭に置く |

## 実行手順

### Step 1: 書く前に、構造を決める

**読み手が何を探しに来るかを先に決め、それを見出しの並びにする。**
本文から書き始めない。

- 読み手が最初に知りたい1つを決め、それを最初の節に置く
- 「決めたこと」と「どうやったか」と「なぜそう判断したか」を、別の節または別のファイルに分ける
- 1つの節が扱う主題を1つにする。見出しが中身を言い切れるかで判定する

### Step 2: 散文にせず、形を選んで書く

**書く内容の種類ごとに、形が決まっている。**
**形を選ぶのは書き手ではなく、情報の型である**
（`references/knowledge/technical-writing-for-research-documents.md` の概念2）。

- 対比・条件・一覧・手順は表で書く
- 分岐・流れ・包含は図で書く
- コードブロックは、コードと出力と木構造だけに使う
- 散文は、理由を述べるときだけに使う

### Step 3: 書いたあと、5観点で検査する

**書き終えてから、次の5つを順に当てる。**
`references/writing-checklist.md` に、各観点の判定の仕方がある。

#### 観点1: 読み手の窓を超えていないか

- 1つの文書が長すぎないか。長ければ、決めたことと手順に分ける
- 1つの節に主題が2つ入っていないか
- 見出しの並びだけを読んで、何が書いてあるか分かるか
- **節も欄も、結論の一文で始まっているか**（面や列の見出しも同じ）
- **理由が連鎖として書かれ、測った段と確かめていない段が分かれているか**
- **1つの記録が扱う決定は1つか。**同じ理由と同じ軸の記録が並んでいないか
- **前の節が、後の節で決まることに依存していないか**
- 抽象から具体へ降りているか。具体から始めて、抽象を言い残していないか

#### 観点2: 同じことを2か所に書いていないか

- 同一の文が2か所に無いか
- 同じ主張を言い換えて繰り返していないか
- 参照先の見出しが、探し物の名前と噛み合っているか

#### 観点3: 語が揺れていないか

- 同じ意味に2つの語を当てていないか
- 違う意味に同じ語を当てていないか
- **別の分野から借りた語を、断らずに使っていないか**
- 普通の日本語を、役割や分類の名前に取っていないか
- 標準的な意味を持つ専門用語を、別の意味で使っていないか

#### 観点4: 情報が散っていないか

- 同じものを説明する記述が、文書のなかで離れた位置に無いか
- 表の列と、本文が論じる項目が一致しているか
- 数値を出した箇所と、その出所を書いた箇所が離れていないか
- **添える情報が、読むために要るなら前、疑うときに要るなら後ろに置かれているか**

#### 観点5: 日本語として読めるか

**どれも禁止ではない。条件で見る。**

- **主語・目的語**——省いた語を、文脈から一意に復元できるか
- **体言止め**——説明の文で続けていないか。表のセル・見出し・箇条書きなら自然である
- **倒置**——主語と述語が離れて、意味が取れなくなっていないか
- **1文の長さ**——2つ以上の命題を運んでいないか。1つなら長くてよい
- **名詞の連結**——初めて見る語を4つ以上つなげていないか
- **指示語**——指す先が離れていないか。候補が複数ないか

#### 観点は、どの概念の現れか

**5つの観点は、検査の当て方である。**
**なぜその観点があるのかは、`references/knowledge/` にある。**

| 観点 | 立っている概念 |
|---|---|
| 1 読み手の窓 | 文書は、探しに来た人のためにある ／ 判断に要る量まで削る |
| 2 同じことを2か所 | 情報の型が、表現の形を決める（1か所に書き、他から参照する） |
| 3 語が揺れていないか | **`ubiquitous-language-in-documents` の4つ** ／ 別の分野の語を借りない |
| 4 情報が散っていないか | 文書は、探しに来た人のためにある |
| 5 日本語として読めるか | 誰が何をするかを、文から復元できるようにする ／ 声に出して読める |

**そして、どの観点にも属さない概念が1つある。**
**概念8「書いたものと、描画されたものは違う」は、書き方ではなく出力の壊れを言う。**
**ガードレールで扱う。**

### Step 4: 検査を機械にも通す

**`references/check_writing.py` を通す。**

```
python3 <skill>/references/check_writing.py <ファイル...>
  --synonyms 用語.tsv   同じ意味に当ててはいけない語の対
  --terms 複合語.tsv    定着した複合語。名詞の連結として指摘しない
  --figures 借用語.tsv  別の分野から借りた語。1行1語
```

**検査は1つずつ、`references/knowledge/` の概念に紐づいている。**
**概念を持たない検査は置かない。**

| 出方 | 検査が見るもの | 紐づく概念 |
|---|---|---|
| **指摘** | 強調が描画されない | 概念8 書いたものと、描画されたものは違う |
| **指摘** | ASCII の罫線 | 概念2 情報の型が、表現の形を決める |
| **指摘** | 語の対（`--synonyms` で与える） | 語彙2 1つの語に1つの意味 |
| 確認 | 体言止め ／ 名詞の連結 | 概念5 誰が何をするかを、文から復元できるようにする |
| 確認 | 1文の長さ | 概念6 判断に要る量まで削る |
| 確認 | 同じ文が2か所にある | 概念1 1か所に書き、他から参照する |
| 確認 | 借用語（`--figures` で与える） | 概念9 別の分野の語を借りない |

**指摘は壊れている。直す。**
**確認は判断が要る**。表のセルが名詞句で終わるように、そのままでよい場合がある。
**読んで決める。**

**悪い例を引用する文書は、先頭に次の印を置くと検査から外れる。**

```
<!-- writing-guard: exempt -->
```

**対象フォルダに独自の検査があれば、それも通す。**

**9つの概念のうち、この検査が触れるのは6つである。**
**概念3・4・7には触れない**
（`references/knowledge/technical-writing-for-research-documents.md`）。
**0件は、通ったという意味であって、読めるという意味ではない。**

### Step 5: 読み手を立てて、確かめる

**機械で見えない範囲を、文脈を持たない読み手に読ませて確かめる。**
手順は `references/knowledge/reader-testing.md` にある。

- **その文書を読む人が実際に持つ問いを、5つから10つ作る**
- **文脈を持たない読み手に、文書だけを渡す。**同じ場で続けて聞かない
- 答えられない箇所・答えが割れる箇所・前提を間違える箇所が、直す場所である
- **問いに一貫して正しく答え、新しい欠けが出なくなったら終わりにする**

**「読みやすいか」と聞かない**。答えが主観になり、直す場所が決まらない。
**輪を回すたびに、問いを作り直す**。同じ問いを使い回すと、直した箇所しか見なくなる。

**論証の順序と、抽象から具体への降り方は、機械で見つけられない。**
見出しの語で照合する検査を試した。普通名詞を拾うだけで、本物を逃した。
**この2つは、読み手を立てるしかない。**

## 出力形式

**直した文書を出す。あわせて、次を報告する。**

| 報告する内容 | 書き方 |
|---|---|
| 直した箇所 | 観点ごとに、どこを何から何へ直したかを表で出す |
| 直さずに残した箇所 | 場所と、残す理由を書く |
| 機械の検査の結果 | 通したスクリプトの名前と、指摘の件数を書く |
| **読み手を立てた結果** | **使った問いと、答えられなかった箇所を書く。立てていないなら、立てていないと書く** |
| 確かめていないこと | **確かめていないことを、確かめたと書かない** |

## ガードレール

- **訂正の記録を本文に残さない。**文書には現行の正しい内容だけを書く。履歴はgitが持つ
- **数値は原典の文字列で確認してから書く。**要約を経由して引かない。自分で計算した値を、原典の値のように書かない
- **確かめていない内容を、確かめたように書かない。**推測は推測と分かる形で書く
- **ASCII で図を描かない。**図は mermaid か SVG で書く
- **名前を付ける前に、検査を書けないか試す。**検査で書けるなら、名前は要らない
- **既存の文書に用語の定めがあれば、それを上書きしない**
- **1つの観点で直したあと、他の観点が壊れていないかを見る。**節を分けると参照が切れ、語を変えると別の箇所と揃わなくなる
- **描画して確かめてから出す。**閉じの強調記号を句点の後ろに置くと、太字にならない。原文を読んでも分からない
- **機械の検査で、読み手を立てる代わりにしない。**9つの概念のうち、触れるのは6つである

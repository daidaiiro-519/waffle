抽象化を求められたとき、情報を減らしてはいけない。**要素の数は変わらず、それを束ねる共通概念が増える**のが抽象。図で表すなら、要素を消すのではなく**区画で囲む**。

**Why:** ユーザーの指摘「抽象は簡略化ではないし、情報の削減ではない。特徴を抽出して共通概念として表現するのが抽象だよ？」。ADRが冗長だと言われて、図の7要素（intent / reading / direction / groups / nodes / edges / notes）を4つのかたまりに潰した。これは削減であり、**仕様で分解しようとしても元の要素が戻らない**。正しくは、7要素を残したまま「意図／描き方の指定／中身／読み方と注釈」という区画で囲む。そうすると「区画は変わらず、意図が主張へ置き換わり、描き方の指定の区画が丸ごと消える」という変更の本体が、要素を失わずに見える。

**How to apply:** 「冗長だ」「認知負荷が高い」と言われたときに削るのは、**粒度が違うもの**（ADRに書いた仕様レベルの詳細＝キー名の列挙・条件の書き方・具体的な数値）であって、**要素そのものではない**。判断の材料は減らさず、束ね方で読みやすくする。あわせて2つ——ADRは仕様への橋渡しだが内容は抽象であり、細部は仕様で決まる。そして「答えないこと」には、**決められるのに決めていないもの**を置かない（そこは決めてから出す）。関連: [[feedback_figure_stays_inside_body_width]] [[project_figure_vocabulary_three_tiers]]

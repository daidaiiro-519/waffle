図（mermaid）の後ろに置く補足は、**図の要素を名指しした注釈の表**（`どこの話か` / `図に載せきれないこと`）で持つ。`KnowledgeSchema/v6` の `figure.notes` として実装済み（2026-08-11）。

**Why:** 図は読み手に推測の余地を残すので、解釈が分かれる。ただし補足として辺の一覧（から／へ／関係）を出すと、図に書いてあることの書き写しにしかならず、読み手の解釈を1つも狭めない（実際に7本で190行を無駄に使っていた）。文章で書くと、図全体への感想へ流れて要素に紐づかなくなる。**表にすると「どこの話か」に図の要素名しか書けないので、どこにも紐づかない一般論を書いた時点でそれが見える。**

**How to apply:**
- 注釈は「その要素について図の見た目からは決められないこと」を書く。分岐なら何を基準に分かれるのか、同じ形の矢印でも意味が違うならその違い、囲みなら中どうしが何を共有し外と何が違うのか、合流なら別々の経路が同じ先へ行くのはなぜか
- 「AからBへ線がある」等の書き写しは書かない。読み違えようのない図なら空でよく、その場合は表が付かない
- `reading` は図全体の1〜2文に留め、要素ごとの注意書きは `notes` へ寄せる（両方に詳細を書くと同じことを二度言う形になる）
- 描画の順は 意図・読み取り → 図 → 注釈の表。仕様は `uc-render-document` の `figure-notes-are-rendered-as-a-table-after-the-figure`

2026-08-29、`.claude/skills/design-svg/svg_engine/`（自前SVG描画エンジン、24モジュール）のアーキテクチャ規律を承認した。
ADR: `docs/adr/adr-contract-tests.html`（承認済み）／commit `b02ade1`。

**1. ヘキサゴナル・クリーンアーキ・オニオンのいずれも採らない。**
3つとも「内側（業務規則）を外側（基盤）の揺れから守る」ために立つが、このエンジンは
中心も外周も空。外部依存0件・I/Oなし・時刻なし・乱数なし・業務規則なし。
Clean自身の言い方では描画ライブラリは「詳細」であり、**このエンジンはWaffleの
クリーンアーキにおける最外周の輪そのもの**。輪の中にもう一枚オニオンを入れ子にする
話ではない。ddd-advisorとtech-lead-advisorへ並列に敵対的検証を依頼し、独立に一致した。

**2. 採るのは「厳格な層状 ＋ パイプとフィルタ ＋ 関数核」。規約は3条。**

| 規約 | 内容 | 承認時の実測 |
|---|---|---|
| 1 | 下から上を呼ばない、層を飛ばさない | 責務で4層（語彙・台帳／方針・配置／部品／合成）を引き直し、下から上への呼び出し**0件** |
| 2 | 段ごとに型が変わり、前の段を飛ばせない | 未着手。`style: dict` が27箇所、`ComponentResult` 生成25箇所 |
| 3 | 契約は中立モジュールが所有し、実装が所有しない | **5違反**。grid/tree/radial/nesting/compose が `sugiyama` から `LayoutResult` を借りている |

**3. 構造で縛れないものは落ちる試験で捕まえ、件数の天井を置く。**
Waffle語彙の漏れ11ファイル・見た目の値の直書き45件。ファイルごとの現在値を天井とし、
下げるのは自由・上げるのは不可。例外表は増える方向にしか動かないので採らない。

**4. 規約2の前に静的検査器を1つ入れる。**
関数150件中114件に型注釈があるのに `pyproject.toml` に mypy も pyright も無い。
いま型注釈は docstring と同じ「宣言だけの契約」。

**2026-08-30、全部実装した。**

| | 結果 |
|---|---|
| 静的検査（mypy、`check_untyped_defs` 有効） | **0件**。46件を天井に載せず全部潰した |
| 規約1（層） | 責務の4層を宣言し、下から上への呼び出し0件を試験で凍結 |
| 規約2（段の型） | `Style` 型へ301箇所を機械置換／`placement` を `OwnOrigin`・`Absolute` の2型へ |
| 規約3（契約の所有者） | `layout_contract.py` を新設し、5箇所の借りを解消 |
| 値の直書き | **0件**（`lint_values` を試験へ配線。検査の誤検出も規則で潰した） |
| 呼ぶ側の語彙（配る側） | **0件** |
| 試験 | 309件 |

パッケージ化も済み（依存0件・Python 3.10以上・まっさらな環境で実証）、
置き場所は `.claude/skills/design-svg/svg_engine/` へ移設済み。

**規約どうしが噛み合って働いた実例が2件ある。**規約1の試験が「土台が方針を知る」違反を
捕まえ、規約2の型の分割が「絶対座標の部品を節点に置く」経路を塞いだ。

**Why:** 同じセッションで「契約はあるが守らせる仕組みが無い」形の欠陥を3件踏んだ。
(a)「Waffle固有の語彙を一切知らない」が3箇所のdocstringで宣言され11ファイルで破れていた
(b) 直書きを禁じる検査 `lint_values.py` は実装済みでどこからも呼ばれず45件放置
(c) `groups` と `layout=` の同時指定で配置戦略が黙って捨てられる実バグ。
層を敷かないと決めた以上、規律を別の形で持つ必要が生じた。

**How to apply:** このエンジンに層・ディレクトリ分割・DI・ポート/アダプタを足す提案は、
実例を伴わない限り採らない（[[project-svg-engine-attachment-redesign]] と同じく、
判断は実測に置く）。新しい規約を足すときは「何を禁じるか」を書けるかで採否を決め、
書けないものは契約ではなく好みとして置かない。宣言（docstring・型注釈）だけを増やす
変更は、照合する仕組みとセットでない限り3度目の同じ失敗になる。
Waffle本体への配置（ポートの位置・変換アダプタの置き場所）はこのADRの外にあり、
`convert()` をWaffle側へ移す判断と合わせて別途決める。

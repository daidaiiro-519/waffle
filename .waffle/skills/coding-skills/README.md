# coding-skills

宣言（言語・アーキテクチャ・形態の選択）を受け取り、適用条件が合う規約だけを集めて出す。

## 単体で動く

このディレクトリを丸ごと持っていけば動く。外の仕組みを呼ばない。

確かめ方 ── 外を指す記述が無いことを見る。

```
grep -rn 'waffle\|\.claude\|document\.json' SKILL.md templates bin
```

何も出なければ、外への参照は無い。

## 中身

| | 何が入っているか |
|---|---|
| `SKILL.md` | 使い方・境界の物差し・ガードレール・道具の呼び方 |
| `templates/` | 文書の形。**新しい文書は必ずここから起こす** |
| `.coding/declarations/` | 宣言。**このディレクトリの外**。使う側が書く |
| `.coding/rules/` ・ `structures/` ・ `behaviors/` | 規約。**このディレクトリの外**。配るときは同梱してよい |

**文書はこの Skill の中には無い。**中身はプロジェクトの持ち物なので、`.coding/` に置く。

```
.coding/
  declarations/     宣言。使う側が書く
  rules/ ・ structures/ ・ behaviors/    規約。配るときは同梱してよい
```

**フォルダは人のためのもの。**機械は前置きの種類で判断するので、1段に置いても同じ一式が出る。

```
conv 初期化 .coding
```

宣言は使う側が書く。規約（`rule-*` ・ `structure-*` ・ `behavior-*`）は、
配るときに同梱してよい ── 条件が合えばそのまま効く。
| `bin/conv` | 集める・並べる・差分を出す・検査する道具（判断は持たない） |

## 道具について

`bin/conv` は、`documents/` を読むだけの道具である。**判断は持たない** ──
並べるところまでが道具で、矛盾かどうか・消すかどうかは読んで決める。

版は `bin/conv --version` で出る。

### いまは Python、ゆくゆくは配られる実行ファイル

**いまは概念を確かめる段なので、この Skill が論理を持っている。**
規約の型（CodingSchema）がまだ無いので、写す先も無い。

型ができた時点で、論理はそちらへ移り、**ここには出来上がった実行ファイルだけが置かれる** ──
同じことを2か所で持つと、片方が古くなったときに気づけないためである。
そのとき `--version` に、作った元の版が入る。

**呼び方（引数と出すもの）は変えない。**先に決めてあるので、中身だけ入れ替わる。

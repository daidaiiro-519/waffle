# 渡ってきた仕様を実装へ落とすときの「どう書くか」を与えるSkill：coding-skills

## 目的

**規約は「どう書くか」だけを与える。「何を作るか」は仕様が与える。**

仕様は外から注入されるものであり、**規約は仕様を知らない**。
知ると向きが逆転し、プロダクトが変わるたびに規約が動く ── これが腐る原因である。

宣言（言語・アーキテクチャ・形態の選択）を受け取り、**適用条件が合う規約だけ**を集めて出す。
規約は1件だけ書かれ、宣言ごとに写さない。

**このSkillは、単体で動く。**外の仕組みを呼ばない。文書の形は `templates/` が持つ。

**文書は、このSkillの中には置かない。**Skill が持つのは
**使い方・形・道具**であって、中身はプロジェクトの持ち物である ──
`.coding/` に置き、`conv 初期化` で作る。

**フォルダは人のためのものである。**機械は前置きの「文書の種類」で判断し、置き場所を見ない。

---

## 語

| 語 | 何であるか |
|---|---|
| 宣言 | 外から注入される軸の値を受け取る口。1本の文書 |
| 選択 | 他がありえたなかで選んだこと。理由と落とした候補を残す |
| 軸 | **その種類の規約を書くために欠かせないもの。**言語・アーキテクチャ・形態の3つ |
| 規約 | 守るべきことを1つ書いたもの。違反しているかを確かめられる |
| 適用条件 | その規約が効く、軸の値の組。**空ならどこでも効く** |
| 文書の種類 | 選択 ／ 規則 ／ 構造 ／ 振る舞い。**背骨（節の並び）を決める** |
| 主題 | 何の話か。**形は決めない**。節は作らず「用語と区分」の中身になる |

---

## 境界　── 規約か、仕様か

**仕様を知らないまま書けるか**で分ける。

| 言明 | 判定 |
|---|---|
| 回復可能な失敗は、値として返す | **規約**（言語だけで書ける） |
| 内側は、外側を知ってはならない | **規約**（アーキだけで書ける） |
| 終了コードは `0` と `0` 以外の2値に留める | **規約**（形態だけで書ける） |
| `validate` が失敗したら終了コード `2` を返す | 仕様 |
| 金額は、誤差の出ない型で扱う | 仕様（何を扱うかを知っている） |

書けないものは、捨てるのではなく**仕様の側へ渡す**。

## 文書の種類と、背骨

| 種類 | 何を決めるか | 違反が見つかる場所 | その種類だけが持つ節 |
|---|---|---|---|
| 選択 | 他がありえたなかで選んだこと | 決めたものと使っているものの食い違い | 選んだもの ／ **落とした候補** ／ この選択がつくる適用条件 ／ 道具 |
| 規則 | どう書くか | コードの一片を読む | 規則一覧 ／ 規則の詳細 |
| 構造 | どう繋ぐか | 依存の向きを辿る | 構成要素 ／ 依存の許可 ／ **違反したとき** |
| 振る舞い | どう動くか | 動かして返る値を見る | 保証する ／ **保証しない**振る舞い ／ 検証の単位 |

どの文書も持つ芯 ── **id ・ 文書の種類 ・ 主題 ・ まとまる理由 ・ 承認 ／ 概要 ／ 用語と区分 ／ 適用範囲外 ／ 委譲する判断 ／ 出典**

**形は `templates/` が持つ。**新しい文書は、必ずそこから起こす。

## 置き方

```
このSkill                    使い方・形・道具。持ち歩く
  SKILL.md ・ templates/ ・ bin/conv

.coding/                     中身。プロジェクトが持つ
  declarations/              選択（宣言）。使う側が書く
  rules/                     規則
  structures/                構造
  behaviors/                 振る舞い
```

**フォルダは人が見つけるためのものである。**機械は前置きの「文書の種類」で判断し、
置き場所を見ない ── 1段に置いても、同じ一式が出る。

**切ってよいのは、文書がその値を1つしか持たないものだけ。**

| 切り方 | 一意に決まるか | 判定 |
|---|---|---|
| 文書の種類 | 1つしか持たない | **切ってよい**（選択も含めて4つとも） |
| 軸 | `language ＋ architecture` のように複数もつ | **切れない** ── 置き場所が決まらない |
| 主題 | 形を決めないもので切ると、種類とずれる | 切らない |

**種類・置き場所・id の頭の3つは、揃っていなければならない**（検査が見る）。
食い違うと、人が迷う ── 機械は迷わないが、人はフォルダで探すからである。

名前は `〈種類〉-〈条件〉-〈主題〉`。フォルダは、その頭の複数形になる。

**宣言は成果物ごとに1つ。**言語やアーキを2つ選ぶなら、それは別の成果物なので、宣言が2つになる。

**宣言は地図ではない。**地図にあたる「一式」は、宣言から**そのつど描く**もので、保存しない。

## 実行手順

### Step 0: 置き場所を作る

```
conv 初期化 .coding
```

4つのフォルダと、宣言の骨が作られる。以後、道具は `.coding` を読む
（別の場所なら `--置き場所` か `CODING_HOME` で指す）。

### Step 1: 宣言を書く

`templates/declaration.md` から起こす。軸の値と、**選んだ理由と落とした候補**を書く。
理由を書けないなら、それは選択ではなく導出であり、記録を持てない。

「何のために作るか」は書かない ── それは仕様が持つ。

### Step 2: 規約を書く

種類に合うテンプレートから起こす。**書く前に、境界の物差しを当てる** ──
「仕様を知らない人が、この言明を書けるか」。

**書く前に、条件が重なる規約を見る**（道具の `重なり`）。重なること自体は正常である
（広い条件と狭い条件）。矛盾かどうかは読んで決める。

### Step 3: 一式を出す

道具の `一式` を使う。**保存しない** ── 選んだ値と適用条件を突き合わせて、そのつど求める。

### Step 4: 選択を変えるとき、差分を見る

道具の `差分` を使う。効かなくなる規約・新たに効く規約が並ぶ。

### Step 5: 画面で見る

```
conv 画面
```

左に、この宣言に効く規約が種類ごとに並ぶ。押すと本文が開く。
**見えるのは描画した姿**であって、記号の並んだ原文ではない。
**保存しない** ── そのつど描いているので、古くならない。

### Step 6: 引き継ぐときは、1枚にまとめて出す

```
conv 落とす dist          1枚の HTML
conv 落とす dist --md     1枚の Markdown
```

**使い捨てである。**出したものを正本にしない ── 正本は `.coding` にある。
**正本のフォルダへは出さない**（出そうとすると止まる）。

### Step 7: 効かない規約を見る

道具の `効かない` を使う。どの宣言にも当たらない規約が並ぶ。
**消すかどうかは読んで決める** ── いま誰も選んでいないだけかもしれない。

## 道具

`bin/conv` に置く。**判断は持たない** ── 並べるところまでが道具で、読んで決めるのは人である。

| 呼び方 | すること | 出すもの |
|---|---|---|
| `conv 一式 [宣言のid]` | その宣言の選択に、適用条件が合う規約を集める（1つしか無ければ省ける） | 種類ごとに、id と主題 |
| `conv 重なり <軸=値> …` | その条件と重なる規約を並べる | id と、その適用条件 |
| `conv 差分 <軸=値> [宣言のid]` | その値に変えたときの入れ替わり | 効かなくなる ／ 新たに効く ／ 変わらない数 |
| `conv 効かない` | どの宣言にも当たらない規約を並べる | id と、その適用条件 |
| `conv 画面 [--port 8732]` | **ローカルサーバーを立て**、絞り込んだ結果を描画して見せる。保存しない | 開く先の URL |
| `conv 落とす <出す先> [--md]` | 一式を**1枚にまとめて**出す。使い捨て | 出した先と、本数 |
| `conv 検査` | 背骨・条件の軸名・**種類と置き場所と id の頭が揃っているか**を見る | 食い違いの一覧。無ければ終了コード `0` |
| `conv 初期化 <置き場所>` | 入口と規約の置き場所を作り、宣言の骨を起こす | 作った場所と、次にすること |
| `conv --version` | この道具の版、作った元の版、出した日、ライセンス | 4行 |

すべて読むだけで、**書き換えない**（`初期化` を除く）。

## ガードレール

- **仕様を規約に取り込まない。**仕様は外から注入される ── 受け取る側が渡す側を知ると向きが逆転し、プロダクトが変わるたびに規約が動く。判定は「**仕様を知らない人が、この言明を書けるか**」
- **規約に固有名を書かない。**書けるのは軸の値のもとで成り立つことだけ。書けないものは捨てるのではなく、仕様の側へ渡す
- **規約を宣言ごとに写さない。**1件だけ書き、適用条件で効かせる
- **置き場所で判断しない。**機械が見るのは前置きの種類と適用条件であって、フォルダではない。フォルダは人が見つけるためのもの
- **1つしか持たない値でだけ、フォルダを切る。**種類は切れる。軸は複数もつことがあるので切れない
- **単独で違反できないものは、規約にしない。**ほかの規約から導かれるものは「そう決めた結果こうなる」に書く
- **主題に節を作らせない。**背骨は種類が決める。主題は「用語と区分」の中身になる
- **公式を書き写さない。**私たちの選択だけを持ち、出典に**引用した文字列と取得日**を書く
- **道具が引き取るものを、規約にしない。**整形の作法は宣言の道具が引き取る
- **選択に違反の節を置かない。**守るべきことではなく、選んだことである
- **軸を勝手に増やさない。**増やせるのは、その軸が無いと書けない規約を実際に1件書けて、かつ**ほかの軸の語では書けない**と確かめたときだけ
- **出したものを正本にしない。**`落とす` は使い捨ての写しであり、正本のフォルダへは出さない
- **画面に原文を映さない。**見せるのは描画した姿である ── 記号の並びを見せても、出来上がりが分からない
- **矛盾を機械で判定しない。**並べるところまでが道具で、読んで決めるのは人
- **効かない規約を自動で消さない。**また効くようになることがある
- **外の仕組みを呼ばない。**このSkillは単体で動く。文書の形は `templates/` が持つ

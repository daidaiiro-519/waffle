# データ契約の構成における確かめる単位

## 概要

**すべての要素がデータ契約だけに依存するので、単体で確かめられる範囲が広い。**

## 保証する振る舞い

| ID | 振る舞い | 検証の単位 |
|---|---|---|
| DP-TB-01 | 写し手は、生の入力とデータ契約の型だけで確かめられる | 単体 |
| DP-TB-02 | 中心の処理は、データ契約の型だけで確かめられる | 単体 |
| DP-TB-03 | 生成した型は、schema と一致する | 結合 |
| DP-TB-04 | 束ねは、すべての写し手を同じ形で呼べる | 結合 |
| DP-TB-05 | すべての写し手が、同じ試験の集合を通る | 単体 |

## 保証しない振る舞い

| 何を | 保証しない理由 | 代わりに何で担保するか |
|---|---|---|
| 接続先が実際に出す形式 | 接続先の版で変わる | 用途の保証規約（実物の記録を材料にする） |
| 実行の口の使い勝手 | 構成からは決まらない | 用途の保証規約 |

## 単位の対応

| 確かめる単位 | 対象 | 用意するもの | 用意しないもの |
|---|---|---|---|
| 単体 | データ契約 | なし | ─ |
| 単体 | 中心の処理 | データ契約の値 | 写し手、外部技術 |
| 単体 | 写し手 | 生の入力の実物（記録から取る） | 中心の処理、他の写し手 |
| 結合 | 束ね | すべての写し手 | 中心の処理 |
| 端から端まで | 実行の口 | 実行できる形の全体 | ─ |

## 契約のテスト

**写し手は全員、同じ試験の集合を通す。**
入力の形は接続先ごとに違うが、**出てくるデータ契約の型は同じ**であるためである。

| 項目 | 内容 |
|---|---|
| 対象 | すべての写し手 |
| 方法 | 「必須の欄が埋まる」「埋まらない欄には理由が付く」を、実物の入力で確かめる |
| 落ちる条件 | 接続先によって、同じ意味の欄が別の形になる |

**共有するのは試験の集合であって、実物の入力ではない。**
この2つを同じ「実物の入力」という語で捉えると、DP-TB-05 と、実物の入力を写し手どうしで共有してよいかの判断（委譲する判断）が衝突して見える。
分ければ衝突しない ── 判定基準は契約の型に対して書かれるので接続先に依らず、
入力は接続先ごとに違うので共有できない。

| 何を | 共有するか | 理由 |
|---|---|---|
| 実物の入力（記録そのもの） | **しない** | 接続先ごとに形が違い、共有すれば接続先どうしが結び付く |
| 試験の集合（判定の側） | **する** | 出てくるデータ契約の型は全写し手で同じ |

**置き場所は言語 × アーキテクチャが決める。**

## 振る舞いの詳細

### DP-TB-01　写し手は、生の入力とデータ契約の型だけで確かめられる

| 項目 | 内容 |
|---|---|
| 前提 | 写し手が中心の処理を知らない |
| 検証の単位 | 単体 |
| 検証方法 | 当たる命令が無い。`cargo tree -p <写し手>` に `core` が現れないかを見る |
| 失敗したときの現れ方 | テストに中心の処理が要る |
| 失敗の切り分け | `core` が現れるなら、写し手が中心の処理を呼んでいる |

### DP-TB-02　中心の処理は、データ契約の型だけで確かめられる

| 項目 | 内容 |
|---|---|
| 前提 | 中心が外部を必要としない |
| 検証の単位 | 単体 |
| 検証方法 | 当たる命令が無い。`cargo tree -p core` に `contract` 以外の自作 crate が現れないかを見る |
| 失敗したときの現れ方 | テストに外部の準備が要る |
| 失敗の切り分け | 写し手が現れるなら、中心が外側を呼んでいる |

### DP-TB-03　生成した型は、schema と一致する

| 項目 | 内容 |
|---|---|
| 前提 | 型が schema から生成されている |
| 検証の単位 | 結合 |
| 検証方法 | `cargo test -p contract` と、そのテストが schema の必須・型・列挙のすべてを当てているか |
| 失敗したときの現れ方 | schema を変えても型が変わらない |
| 失敗の切り分け | 通るのに食い違うなら、テストが当てていない欄がある |

### DP-TB-04　束ねは、すべての写し手を同じ形で呼べる

| 項目 | 内容 |
|---|---|
| 前提 | 写し手の関数の形がそろっている |
| 検証の単位 | 結合 |
| 検証方法 | `cargo test -p bundle` と、そのテストがすべての写し手を同じ形で呼んでいるか |
| 失敗したときの現れ方 | 接続先を足すと束ねが壊れる |
| 失敗の切り分け | 1つだけ別の呼び方なら、束ねに分岐が入っている |

### DP-TB-05　すべての写し手が、同じ試験の集合を通る

| 項目 | 内容 |
|---|---|
| 前提 | 出てくるデータ契約の型が、全写し手で同じ |
| 検証の単位 | 単体 |
| 検証方法 | `cargo test --workspace` と、共通の試験の集合がどの写し手からも同じ形で引かれているか |
| 失敗したときの現れ方 | 接続先によって、同じ意味の欄が別の形になる |
| 失敗の切り分け | 通るのに実装で結果が変わるなら、集合を引いていない写し手がある |

## 適用範囲外

| 何を | どの層が決めるか |
|---|---|
| テストが走る仕組み | 言語 |
| テストの置き場所 | 言語 × アーキテクチャ |
| どの単位にどれだけ厚みを置くか | 用途 |

## 委譲する判断

| 委譲する判断 | 委譲先 | 委譲する理由 |
|---|---|---|
| 実物の入力をどこまで揃えるか | 用途 | 接続先の数と版の幅で決まる |
| 実物の入力を写し手どうしで共有してよいか | 実装 | 外部に原典が無い。依存の規約が写し手どうしの依存を認めていないことを手掛かりに、実装が決める |

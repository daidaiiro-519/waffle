# MCP サーバーのテストの重心と計画

## 概要

**手順が決まっているので、やり取りの順序を端から端まで確かめる。**

## 保証する振る舞い

| ID | 振る舞い | 検証の単位 |
|---|---|---|
| MC-TS-01 | 重心の配分どおりにテストが在る | ─ |
| MC-TS-02 | すべてのテストが、変更のたびに走る | ─ |

## 振る舞いの詳細

### MC-TS-01　重心の配分どおりにテストが在る

| 項目 | 内容 |
|---|---|
| 前提 | 単位ごとに件数を数えられる |
| 検証の単位 | ─ |
| 検証方法 | 当たる命令が無い。単位ごとのテスト件数を数え、重心の高い単位が最も多いかを見る |
| 失敗したときの現れ方 | 端から端までが薄いまま公開される |
| 失敗の切り分け | 数が合っていても薄いなら、1件あたりが確かめる幅が広すぎる |

### MC-TS-02　すべてのテストが、変更のたびに走る

| 項目 | 内容 |
|---|---|
| 前提 | 実行が1つの命令で済む |
| 検証の単位 | ─ |
| 検証方法 | 当たる命令が無い。変更を取り込む設定に、すべてのテストを走らせる段が在るかを見る |
| 失敗したときの現れ方 | 走らないテストが残る |
| 失敗の切り分け | 走っているのに落ちないなら、除外の指定が効いている |

## 重心

| 確かめる単位 | 重心 | 根拠 |
|---|---|---|
| 単体 | 高 | 能力の中身は、やり取りを用意せずに確かめられる |
| 結合 | 中 | メッセージの解釈と組み立てを確かめる |
| 端から端まで | **高** | 初期化から終了までの順序が、仕様で決まっている |
| 性能 | 低 | 仕様が速さを定めていない |

## 採るテスト観点

| 観点 | 採否 | 理由 |
|---|---|---|
| 正常系 | 採る | 手順どおりのやり取りを保証している |
| 異常系 | 採る | 失敗を接続を切らずに返すことを保証している |
| 境界値 | 採る | メッセージの大きさに上限を置いている |
| 後方互換 | 採る | 版を申告して接続する |
| 順序非依存 | 採らない | 手順そのものが順序を定めている |
| 冪等性 | 保留 | 能力の性質による。能力ごとに決める |
| 並行性 | 保留 | 同時に複数の呼び出しを受けるかは、実装で決める |
| 障害注入 | 採らない | 外部への通信を持たない |

## テストの計画

| 項目 | 定め |
|---|---|
| 実行のタイミング | コミット前（ローカル）と、変更の取り込み時（CI） |
| 通過の条件 | すべて緑。端から端までのやり取りが仕様の順序どおり |
| 実行の上限 | 全体で1分以内 |
| 対象外 | 負荷試験 |

## カバレッジの扱い

| 項目 | 定め |
|---|---|
| 下限 | **置かない**（数値は振る舞いを保証しない） |
| 使い方 | 未到達の一覧を、確かめ漏れの発見に使う |

## 適用範囲外

| 何を | どの層が決めるか |
|---|---|
| 確かめる単位の境界 | アーキテクチャ |
| テストが走る仕組み | 言語 |

## 委譲する判断

| 委譲する判断 | 委譲先 | 委譲する理由 |
|---|---|---|
| 冪等性・並行性の採否 | 実装 | 提供する能力の性質で決まる |

# バックエンドAPI が保証する振る舞い

## 概要

**呼び出し元から見た状態コード・応答の形・再送時の扱いを保証し、内部の作りは保証しない。**

## 保証する振る舞い

| ID | 振る舞い | 検証の単位 |
|---|---|---|
| BA-AC-01 | 契約どおりの要求に、契約どおりの状態コードと応答を返す | 端から端まで |
| BA-AC-02 | 契約に合わない要求は 400 で返し、どの欄が問題かを示す | 結合 |
| BA-AC-03 | 同じ要求識別子での再送は、二重に反映されない | 端から端まで |
| BA-AC-04 | 依存が失敗しても、内部の詳細を応答へ出さない | 結合 |
| BA-AC-05 | 停止の合図を受けても、処理中の要求は最後まで返る | 端から端まで |

## 保証しない振る舞い

| 何を | 保証しない理由 | 代わりに何で担保するか |
|---|---|---|
| 応答の速さ | 環境で変わる | 運用での計測（この規約の外） |
| 内部のパッケージ構成 | 呼び出し元から観測できない | 層の規約と依存の検査 |
| 依存の実物の振る舞い | 依存の版で変わる | 契約のテスト |

## 振る舞いの詳細

### BA-AC-01　契約どおりの要求に、契約どおりの状態コードと応答を返す

| 項目 | 内容 |
|---|---|
| 前提 | 依存が起動している |
| 入力 | 契約に定めた要求 |
| 期待する結果 | 契約に定めた状態コードと応答の本体 |
| 検証の単位 | 端から端まで |
| 検証方法 | `go test -race -run TestAcceptance_Contract ./...` と、そのテストが、状態コードと応答の本体の両方を当てているか |
| 失敗したときの現れ方 | 状態コードか応答の形が違う |
| 失敗の切り分け | 状態コードだけが合うなら、応答の形が契約から外れている |

### BA-AC-02　契約に合わない要求は 400 で返し、どの欄が問題かを示す

| 項目 | 内容 |
|---|---|
| 前提 | 依存が起動している |
| 入力 | 必須の欄を欠いた要求と、型の合わない要求 |
| 期待する結果 | 状態コード 400 と、問題の欄を指す応答 |
| 検証の単位 | 結合 |
| 検証方法 | `go test -race -run TestAcceptance_BadRequest ./...` と、そのテストが、どの欄が問題かまで当てているか |
| 失敗したときの現れ方 | 500 になる、または欄が示されない |
| 失敗の切り分け | 500 が返るなら、検証の前に処理が始まっている |

### BA-AC-03　同じ要求識別子での再送は、二重に反映されない

| 項目 | 内容 |
|---|---|
| 前提 | 呼び出し元が要求識別子を付ける |
| 入力 | 同じ識別子の要求を2回送る |
| 期待する結果 | 反映は1回。2回目は1回目と同じ応答を返す |
| 検証の単位 | 端から端まで |
| 検証方法 | `go test -run TestIdempotency ./...` と、そのテストが、言明どおりの条件を確かめているか |
| 失敗したときの現れ方 | 2度反映される |
| 失敗の切り分け | 2度反映されるなら、識別子の記録が効いていない |

### BA-AC-04　依存が失敗しても、内部の詳細を応答へ出さない

| 項目 | 内容 |
|---|---|
| 前提 | 依存を失敗させられる |
| 入力 | 依存が失敗する条件での要求 |
| 期待する結果 | 状態コード 500 と、内部の詳細を含まない応答。詳細は記録へ出る |
| 検証の単位 | 結合 |
| 検証方法 | `go test -race -run TestAcceptance_DependencyFailure ./...` と、そのテストが、応答に内部の詳細が出ないことを当てているか |
| 失敗したときの現れ方 | 内部の詳細が応答に出る |
| 失敗の切り分け | 応答に接続先が出るなら、失敗をそのまま文字列にしている |

### BA-AC-05　停止の合図を受けても、処理中の要求は最後まで返る

| 項目 | 内容 |
|---|---|
| 前提 | 停止の合図を送れる |
| 入力 | 処理中に `SIGTERM` を送る |
| 期待する結果 | 処理中の要求は完了し、新しい要求は断られる |
| 検証の単位 | 端から端まで |
| 検証方法 | `go test -run TestGracefulShutdown ./...` と、そのテストが、言明どおりの条件を確かめているか |
| 失敗したときの現れ方 | 処理中が打ち切られる |
| 失敗の切り分け | 打ち切られるなら、受け付けの停止と待機の順が逆 |

## テストの構成

| 種類 | 対象 | 置き場所 | 実行の速さ |
|---|---|---|---|
| 単体 | 業務モデル・業務操作 | 同じパッケージ | 1件あたり数ミリ秒 |
| 結合 | 入力アダプタ・出力アダプタ | 外部パッケージ | 1件あたり数十ミリ秒 |
| 端から端まで | 起動した実行ファイル | `test/e2e` | 1件あたり1秒以内 |

## 適用範囲外

| 何を | どの層が決めるか |
|---|---|
| 確かめる単位の境界 | アーキテクチャ |
| テストが走る仕組み | 言語 |

## 委譲する判断

| 委譲する判断 | 委譲先 | 委譲する理由 |
|---|---|---|
| 依存を実物で確かめるか、代役で確かめるか | 実装 | 用意できる環境で決まる |

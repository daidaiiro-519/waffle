# Rust におけるテストの仕組み

## 概要

**テストは言語の仕組みで走らせ、名前で振る舞いを述べる。**

## 保証する振る舞い

| ID | 振る舞い | 検証の単位 |
|---|---|---|
| RS-TST-01 | すべてのテストが `cargo test` 1つで走る | 単体・結合 |
| RS-TST-02 | テストは実行順に依存せず、単独でも走る | 単体 |

## 保証しない振る舞い

| 何を | 保証しない理由 | 代わりに何で担保するか |
|---|---|---|
| 外部サービスとの結合 | 言語の仕組みでは決まらない | 用途の保証規約 |
| 網羅率の下限 | 数値の下限は振る舞いを保証しない | レビュー |

## 振る舞いの詳細

### RS-TST-01　すべてのテストが `cargo test` 1つで走る

| 項目 | 内容 |
|---|---|
| 前提 | 単体テストは対象と同じファイルの `#[cfg(test)] mod tests` に、結合テストは `tests/` に置く |
| 入力 | なし |
| 期待する結果 | 走ったテスト数が、書いたテスト数と一致する |
| 検証の単位 | 単体・結合 |
| 検証方法 | **`cargo test`**（素で走らせる）。<br>**`--all-targets` を付けない**——付けると文書の例が走らない |
| 失敗したときの現れ方 | 走らないテストが残り、CI が通ってしまう |
| 失敗の切り分け | 走らないテストが在れば、置き場所が標準から外れている |

### RS-TST-02　テストは実行順に依存せず、単独でも走る

| 項目 | 内容 |
|---|---|
| 前提 | 可変な共有状態（グローバル変数・固定パスの一時ファイル）を持たない |
| 入力 | なし |
| 期待する結果 | 並列でも単独でも、同じ結果になる |
| 検証の単位 | 単体 |
| 検証方法 | `cargo test` と `cargo test -- --test-threads=1` の両方 |
| 失敗したときの現れ方 | 並列実行で落ちる |
| 失敗の切り分け | 片方だけ落ちるなら、共有状態が残っている |

## 走らせ方

| 項目 | 定め |
|---|---|
| 実行コマンド | **`cargo test`**。これ1つで、単体 ・ 結合 ・ 文書の例が走る |
| 検出のされ方 | `#[test]` を付けた関数が走る。`tests/` の各ファイルは1つの実行単位になる |
| **`--all-targets` の落とし穴** | **付けると文書の例が走らなくなる。**実測——doc テスト1件の crate で、素の `cargo test` は `Doc-tests` を走らせ、`--all-targets` を付けると `Doc-tests` の束が0個になった |
| 並列 | 既定でスレッド並列。順序に依存するテストは書かず、`--test-threads=1` は切り分けにだけ使う |
| 絞り込み | 名前の一部を渡して絞る。`--ignored` で普段外しているものだけを走らせる |
| 失敗の表示 | 期待と実際の両方を出す。`--nocapture` で標準出力も見る |

## テストの書き方

| 項目 | 規則 |
|---|---|
| 名前 | 振る舞いを述べる文にする。実装の名前を含めない |
| 構成 | 前提・実行・確認の3段に分ける |
| 表明 | 失敗時に、期待と実際の両方が出る形で書く |

**適合例**

```rust
#[test]
fn a_port_outside_the_range_is_refused() {
    let result = read_port("70000");
    assert!(matches!(result, Err(ParsePortError::OutOfRange { got: 70000 })));
}
```

**違反例**

```rust
#[test]
fn test_read_port_2() {
    assert!(read_port("70000").is_err());
}
```

**名前は、綴りの規則に従う**（`RS-STY-02`）。
日本語で書くと読みやすいが、**`snake_case` ではない**。
実測——日本語の関数名は `cargo clippy -- -D non_snake_case` を**指摘0件で通る**。
検査が落とさないので、**規約の文言だけが守られなくなる**。

## テストの構成

| 種類 | 対象 | 置き場所 | 実行の速さ |
|---|---|---|---|
| 単体 | 1つの関数・型の振る舞い | 対象と同じファイルの `mod tests` | 1件あたり数ミリ秒 |
| 結合 | 公開する境界の振る舞い | `tests/` | 1件あたり数十ミリ秒 |

## 適用範囲外

| 何を | どの層が決めるか |
|---|---|
| 層ごとにどこへテストを置くか | 言語 × アーキテクチャ |
| 何を保証するか | 用途 |

## 委譲する判断

| 委譲する判断 | 委譲先 | 委譲する理由 |
|---|---|---|
| 性質テスト（proptest 等）を使うか | 用途 | 入力の広さは、外部との契約で決まる |

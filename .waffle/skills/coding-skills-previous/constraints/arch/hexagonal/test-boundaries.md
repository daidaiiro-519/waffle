# 確かめる単位の境界

## 概要

**内と外が分かれているから、確かめる単位が決まる。**
何を単体とし、何を結合とするかは、構成要素の境界がそのまま答えになる。

## 保証する振る舞い

| ID | 振る舞い | 検証の単位 |
|---|---|---|
| HX-TB-01 | 業務モデルの規則は、外部を用意せずに確かめられる | 単体 |
| HX-TB-02 | 業務操作は、二次のポートの偽物だけで確かめられる | 単体 |
| HX-TB-03 | 出力アダプターは、二次のポートの契約を満たす | 結合 |
| HX-TB-04 | 入力アダプターは、外部の形式を一次のポートの型へ写す | 結合 |
| HX-TB-05 | ポートの形は1か所で定め、実装はそれと一致する | 結合 |
| HX-TB-06 | 1つのポートに差さるアダプターを、同じ形で呼べる | 結合 |
| HX-TB-07 | 同じポートに差さるアダプターは、同じ試験の集合を通る | 単体 |

## 保証しない振る舞い

| 何を | 保証しない理由 | 代わりに何で担保するか |
|---|---|---|
| 外部サービスの実際の応答 | この構成要素は外部が何かを知らない | 用途の保証規約 |
| 性能 | 構成要素の並びからは決まらない | 用途の保証規約 |

## 単位の対応

| 確かめる単位 | 対象 | 用意するもの | 用意しないもの |
|---|---|---|---|
| 単体 | 業務モデル | なし | 二次のポートの偽物も要らない |
| 単体 | 業務操作 | 二次のポートの偽物 | 実装アダプター、外部技術 |
| 結合（契約） | 出力アダプター | 実装1つと、外部技術の代役 | 業務操作 |
| 結合（境界） | 入力アダプター | 一次のポートの型だけ | 業務操作、外部技術 |
| 結合（形） | ポートの形 | 形の正（定義）1つ | 実装 |
| 端から端まで | 全体 | 実行できる形の全体 | ─ |

## 契約のテスト

**1つのポートにアダプターが2つ以上あるなら、同じ試験を全部へ当てる。**
片方だけが満たす契約は、契約ではなく実装の都合である。
**一次と二次の、どちらのポートにも当てはまる**——
原文が `There will typically be multiple adapters for any one port` と述べており、
数が2つ以上になるのは、どちらの側でも同じである。

| 項目 | 内容 |
|---|---|
| 対象 | そのポートに差さるアダプターすべて |
| 方法 | 同じ試験の集合を、アダプターごとに走らせる |
| 落ちる条件 | アダプターによって結果が変わる |
| **呼び忘れを防ぐ** | **アダプターの側で呼ばない。**ポートが持つ一覧を回して、機械が全部に当てる |

## 振る舞いの詳細

### HX-TB-01　業務モデルの規則は、外部を用意せずに確かめられる

| 項目 | 内容 |
|---|---|
| 前提 | 業務モデルが外部技術を知らない |
| 検証の単位 | 単体 |
| 検証方法 | 業務モデルの依存に、外側の要素と外部技術が現れないかを見る。**当てる手段は言語が決める** |
| 失敗したときの現れ方 | テストに外部の準備が要る |
| 失敗の切り分け | テストに準備が要るなら、モデルが外部を呼んでいる |

### HX-TB-02　業務操作は、二次のポートの偽物だけで確かめられる

| 項目 | 内容 |
|---|---|
| 前提 | 二次のポートが宣言されている |
| 検証の単位 | 単体 |
| 検証方法 | 業務操作の依存に、アダプターが現れないかを見る。**当てる手段は言語が決める** |
| 失敗したときの現れ方 | テストに実装アダプターが要る |
| 失敗の切り分け | 偽物以外の準備が要るなら、業務操作が外側を直接呼んでいる |

### HX-TB-03　出力アダプターは、二次のポートの契約を満たす

| 項目 | 内容 |
|---|---|
| 前提 | 実装が1つ以上ある |
| 検証の単位 | 結合 |
| 検証方法 | 当たる命令が無い。出力アダプターのテストと偽物のテストが、同じ試験の集合を通っているかを見る |
| 失敗したときの現れ方 | 差し替えると振る舞いが変わる |
| 失敗の切り分け | 片方だけ通るなら、偽物が契約より緩い |

### HX-TB-04　入力アダプターは、外部の形式を一次のポートの型へ写す

| 項目 | 内容 |
|---|---|
| 前提 | 一次のポートの型が定まっている |
| 検証の単位 | 結合 |
| 検証方法 | 入力アダプターのテストが、外部の形式から一次のポートの型までを通しで確かめているかを見る |
| 失敗したときの現れ方 | 形式の変換で欠落が出る |
| 失敗の切り分け | 途中の型で止まっているなら、写しの一部が確かめられていない |

### HX-TB-05　ポートの形は1か所で定め、実装はそれと一致する

| 項目 | 内容 |
|---|---|
| 前提 | ポートの形の正が、1か所に在る |
| 検証の単位 | 結合 |
| 検証方法 | 形の正と、実装が使う型を突き合わせる |
| 失敗したときの現れ方 | **形を直したのに、片方だけが古いまま通る** |
| 失敗の切り分け | 2か所に書いてあるなら、必ずどちらかが古くなる |

### HX-TB-06　1つのポートに差さるアダプターを、同じ形で呼べる

| 項目 | 内容 |
|---|---|
| 前提 | そのポートにアダプターが2つ以上ある |
| 検証の単位 | 結合 |
| 検証方法 | ポートを通して、すべてのアダプターを同じ手で呼ぶ |
| 失敗したときの現れ方 | アダプターごとに呼び方が違い、**呼ぶ側が接続先を知ることになる** |
| 失敗の切り分け | 呼ぶ側に接続先ごとの分岐が現れたら、形が揃っていない |

### HX-TB-07　同じポートに差さるアダプターは、同じ試験の集合を通る

| 項目 | 内容 |
|---|---|
| 前提 | 共通の試験の集合が在る |
| 検証の単位 | 単体 |
| 検証方法 | **ポートが持つ一覧を回して、機械が全部へ当てる** |
| 失敗したときの現れ方 | **アダプターを足したとき、そのアダプターだけ試験を通らない** |
| 失敗の切り分け | アダプターの側で呼んでいるなら、呼び忘れが落ちない |

## 適用範囲外

| 何を | どの層が決めるか |
|---|---|
| テストが走る仕組み | 言語 |
| テストの置き場所 | 言語 × アーキテクチャ |
| どの単位にどれだけ厚みを置くか | 用途 |

## 委譲する判断

| 委譲する判断 | 委譲先 | 委譲する理由 |
|---|---|---|
| 端から端までのテストを持つかどうか | 用途 | 外部との接続の有無で決まる |
| 偽物を手で書くか、道具で作るか | 言語 | 言語の仕組みで変わる |

# 規則の芯 ── 全種類で同じ形

## 概要

**規則1件は、詳細の塊1つである。**
その塊のうち、**種類によらず同じ部分をここが定める**。
種類ごとの欄は、それぞれの雛形（`style.md` ・ `acceptance.md` など）が定める。

**この雛形を写して使うのではない。**
規約を書くときは種別の雛形を写し、芯の形はここを見る。

## 芯

| 何 | どこに書くか | 形 |
|---|---|---|
| ID | 塊の見出し | 見出しの前半。`### 《ID》` |
| 言明 | 塊の見出し | 見出しの後半。検査できる最小の一文。理由も例外も混ぜない |
| 検証方法 | 塊の表の欄 | 走らせる命令と、その命令で落ちない部分の見る箇所 |
| 出典 | `## 出典` の、同じ ID の行 | 種類・原典・版と取得日・何を裏づけるか |

**塊の見出しと、塊の表の欄。**

```
### 《ID》　《言明を一文で》

| 項目 | 内容 |
|---|---|
| 検証方法 | `《走らせる命令》` と、《その命令で落ちない部分の、見る箇所》 |
《ここから下は、種別の雛形が定める欄》
```

**出典の行。**

```
| 《ID》 | 《規格／文献／実測》 | 《書名・URL》 | 《版と取得日》 | 《何を裏づけるか》 |
```

**出典だけは塊の外に置く。**
同じ表に全規則ぶんが並ぶので、原典の重なりが一目で分かる。
ID で結ばれ、`check.py` が両方向から突き合わせる ──
出典を持たない規則も、規則を持たない出典も落ちる。

## 一覧は書かない

**規則の一覧は導出物である。**
`python3 scripts/relist.py` が詳細の塊から書き出す。
**どの列を持つかは、種別の雛形の一覧の表が宣言する。**

手で書くと詳細と食い違う ──
実際に、一覧と詳細の両方に在る欄105件のうち36件で値が食い違っていた。

## 種類ごとの欄

| 種別 | 足す欄 |
|---|---|
| `style` ・ `failure` ・ `concurrency` ・ `test-placement` | 水準・適用範囲・根拠・例外・既存コードへの適用 |
| `acceptance` ・ `test-mechanism` | 前提・入力・期待する結果・検証の単位・失敗したときの現れ方・失敗の切り分け |
| `test-boundaries` ・ `test-strategy` | 前提・検証の単位・失敗したときの現れ方・失敗の切り分け |

**この表は、それぞれの雛形の詳細の表から読める。**
`check.py` の「詳細の塊が、芯と種類ごとの欄を持つ」が、正本と突き合わせる。

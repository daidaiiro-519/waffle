# 共有されるHTMLの契約

artifact-share が配信するHTMLが満たすべき取り決め。
既定テンプレートを使う場合も、独自テンプレートを作る場合も、他所で作った完成済みHTMLを持ち込む場合も、
公開できるかどうかはこの契約を満たすかどうかだけで決まる。配信側は、そのHTMLがどう作られたかを知らない。

読む相手は3種類いる。

- 既定テンプレートを使うだけの人 — 満たしていることは保証済みなので、この文書を読む必要はない
- 独自テンプレートを作る人 — この文書が仕様書になる
- 完成済みHTMLを持ち込む人 — 「1. 自己完結」だけ確認すればよい

---

## 1. 自己完結していること（必須）

外部のホストからCSS・JavaScript・フォント・画像を読み込まない。すべてHTMLの中に含める。

これは規約ではなく、**配信時のレスポンスヘッダー（CSP）で機械的に強制される**。
外部を参照していても公開はできるが、閲覧者の環境ではその読み込みがブラウザに止められ、見た目が崩れる。

| 書き方 | 可否 |
|---|---|
| `<style>` によるインラインCSS | 可 |
| `<script>` によるインラインJavaScript | 可 |
| `data:` URI で埋め込んだ画像・フォント | 可 |
| `<link rel="stylesheet" href="https://...">` | **止められる** |
| `<script src="https://...">` | **止められる** |
| `<img src="https://...">` | **止められる** |
| `fetch()` による外部への通信 | **止められる** |

アップロード時にこれらの参照は検出され、公開前に件数が知らされる。

---

## 2. サンドボックス内で動くことの帰結（知っておくべき制約）

公開されたHTMLは、閲覧画面の中で `sandbox` 属性付きの iframe として読み込まれる。
`allow-same-origin` は付与されない。したがって次のことが**できない**。

- 閲覧トークンのCookieを読むこと
- `localStorage` / `sessionStorage` を使うこと
- 同じドメイン上の他のアーティファクトやコメントAPIへ通信すること
- 外側のコメント欄の内容を読んだり書き換えたりすること

これは制限ではなく**保護**である。悪意のあるHTML、あるいは中身を精査せずに持ち込まれたHTMLが、
閲覧者のトークンを盗んだり、他の人のアーティファクトを読み出したりする経路を、ブラウザの仕組みとして塞いでいる。

一方、次のことは**できる**。

- インラインJavaScriptによる操作（タブの切り替え、折りたたみ、図の描画など）
- ページ内リンク（`#anchor`）による移動
- 他のアーティファクトへのリンク（`<a href>`）。クリックすると外側の画面ごと遷移する

見出しに `id` を持たせておくと、`/p/{slug}/#その id` というURLでその位置を開ける（閲覧画面がハッシュを中身へ引き継ぐ）。
必須ではなく、`id` が無ければ先頭から表示されるだけ。ただし、目次を押してもアドレスバーは変わらないため、
節を指すURLは手で組み立てることになる。

DOMは外側と完全に分かれているため、**id やクラス名が外側とぶつかる心配はない**。好きな名前を使ってよい。

---

## 3. メタ情報を持たせる（任意・持つと公開が速い）

`<head>` に次のタグを置くと、アップロード時に自動で読み取られ、**入力欄が1つも出ないまま公開できる**。

```html
<meta name="id" content="adr-search-backend-pg-trgm">
<meta name="type" content="DecisionRecord">
<meta name="title" content="検索基盤にPostgreSQLの全文検索を採用する">
<meta name="description" content="案件検索の実装で、新規ミドルウェアではなく既存DBの拡張機能を採用する設計決定記録">
<meta name="tags" content="backend, search, database, adr">
```

| タグ | 役割 |
|---|---|
| `id` | 文書の識別子。ソース全体で一意にする。文書どうしのリンクを辿るときの手がかりになる |
| `type` | 文書の種別。**artifact-share は値の意味を解釈しない**。任意の文字列でよく、一覧での絞り込みにだけ使われる |
| `title` | 表示名。無ければ `<title>` が使われる |
| `description` | 一覧で中身を選ぶための一文。**受け取った側にとって最も重要な情報**なので、書いておくと親切 |
| `tags` | カンマ区切りの分類。**閲覧できる範囲を変える力は持たない**（後述） |

これらが無いHTMLも公開できる。その場合は表示名だけを尋ねられる。

この形式は document-graph の契約と同じもので、他のツールと共通に使える。

---

## 4. タグは分類であって、権限ではない

`tags` はHTMLの中に書かれた値、つまり**アップロードする人が自由に決められる値**である。
したがって、これが閲覧できる範囲を決めることは無い。決めていたら、metaタグを1行書き換えるだけで
他人のプロジェクトに紛れ込めてしまう。

閲覧できる範囲を決めるのは次の2つだけで、いずれも**人の明示的な操作**による。

| | 決め方 | 効果 |
|---|---|---|
| 個別のトークン | 公開時に発行される | そのアーティファクト1件を開ける |
| プロジェクトの所属 | アップロード時か管理画面で選ぶ | そのプロジェクトのトークンで、入っているものを開ける |

---

## 5. URLとファイルの置かれ方

公開すると、slug（短いランダムな識別子）が発行され、次のように配置される。

```
/p/{slug}/            閲覧画面。コメント欄を持ち、下の content.html を iframe で読み込む
/p/{slug}/content.html  アップロードされたHTML。中身は一切変更されない
/comments/{slug}/     コメント。1件が1ファイル
```

アップロードしたHTMLは**バイト単位でそのまま保存される**。プレースホルダーの置換も、タグの挿入も行わない。
エクスポートすると、この `content.html` がそのまま取り出せる。

種別ごとにURLの形が変わることはない。すべての文書が `/p/{slug}/` を共有する。

---

## 6. 満たさなくてよいこと

紛らわしいので明記しておく。次のものは**契約に含まれない**。

- コメント欄のマークアップを持つこと — 閲覧画面（外側）が持つ。中身は関知しない
- 特定の見出し構造・セクション構成 — 既定テンプレートの2層構造は、そのテンプレート固有の設計であって契約ではない
- 特定のCSSクラス名・命名規則 — サンドボックスで隔離されているため衝突しない
- 単一ファイルであること — 実体は1つのHTMLファイルだが、その中の構造は自由

---

## 補足：なぜ iframe なのか

自己完結HTMLは、その定義上インラインのJavaScriptを含む。それを外側のページに直接埋め込むと、
`script-src 'unsafe-inline'` を許さざるを得ず、**持ち込まれた任意のJavaScriptが、
閲覧トークンやコメントAPIと同じオリジンで動く**ことになる。CSPではこの構造を止められない。

`allow-same-origin` を付けない iframe に入れると、その中身は不透明なオリジンとして扱われ、
Cookieにも同一オリジンの通信にも手が届かなくなる。追加の費用もサーバー側の処理も要らず、
ブラウザの仕組みだけで境界が成立する。

アップロードできるのは招待された人だけなので、悪意のあるHTMLが持ち込まれる可能性は低い。
それでも隔離するのは、**「中身を精査せずに上げてしまった」という事故の方が現実的に起こりやすい**ためである。

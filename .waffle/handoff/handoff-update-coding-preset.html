02 詳細

orchestrator（advisor未相談・要レビュー）
戻す単位はブロック。丸ごとの写しにしない
プリセットは汎用、プロダクトの規約は固有の判断を含む。実際に architecture の coveredContexts はプロダクト固有で、プリセットは持っていない。丸ごと写すとこうした項目がプリセットへ紛れ込み、無関係なプロダクトへ余計な制約が配られる。何が汎用かの判断は人が持ち、機械は指定されたブロックの反映だけを担う。
orchestrator（advisor未相談・要レビュー）
反映はプリセットへの一方向に限る
プリセットとプロダクトの双方向同期にすると、どちらが正かが場面ごとに変わり、宣言の出どころが決まらなくなる。プロダクトの規約はプロダクトが持ち、プリセットへは一方向に反映する、という向きを固定する。プロダクト側は決して書き換えない。なお、この操作は指定されたブロックを反映先の内容で置き換えるので、複数のプロダクトから同じブロックへ反映すると最後の1つが残る。複数の経験を蓄積する形にはなっていない。
orchestrator（advisor未相談・要レビュー）
プリセットが持たないブロックへは書き込まない
プリセットの語彙を、反映のたびに増やせるようにしない。プリセットが持っていない項目を書き込めると、どのプロダクトの都合でその項目が入ったのかが後から辿れなくなる。プリセットの構成を変えるのは、プリセットそのものを設計し直す別の判断。
orchestrator（advisor未相談・要レビュー）
内容が一致していれば書き換えない
無変更の書き込みは、ファイルの更新を見ている周辺の仕組みには変更と区別がつかない。既存の clear_field / migrate_schema / fill と同じく、変更の有無を返し、変更が無ければ保存しない。
orchestrator（advisor未相談・要レビュー）
プリセットの読み書きポートに書き込みを足す
CodingPresetRepository は load / list_names だけで、書き込む口が無い。save を足す。プリセットはパッケージ内（waffle/domain/model/CodingPresets/）に置かれ、importlib.resources で解決される。書き込みはソースツリーに対する操作であり、インストール済みパッケージへの書き込みを意図しない点を制約として記録する。
orchestrator（advisor未相談・要レビュー）
対象の種類は出どころの規約から決まる
プリセットは tech-stack / architecture / coding-standard / test-standard の4種類を持つ。どれへ反映するかは、出どころの規約が持つ codingKind から決まるので、呼び出し側に指定させない（指定させると、取り違えた組み合わせを受け付けてしまう）。

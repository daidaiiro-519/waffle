# Go ・ hexagonal における要素の置き場所

## 概要

依存の向きを、パッケージの分け方で守らせる。

## 用語と区分

| 語 | 意味 |
|---|---|
| 内側 | 判断を持ち、入出力をしない部分 |
| 入口 | 外から呼ばれる部分。形態ごとに1つ |

## 規則一覧

| ID | 言明 | 水準 | 適用範囲 |
|---|---|---|---|
| GH-PL-01 | 内側は1つのパッケージに置き、外部技術を読み込まない | 必須 | 内側 |
| GH-PL-02 | 入口ごとにパッケージを分け、入口どうしは読み込まない | 必須 | 外側 |
| GH-PL-03 | 偽物は内側のテストの中に置き、入口のパッケージへ置かない | 必須 | 内側のテスト |
| GH-PL-04 | 単体テストは、対象と同じパッケージに置く | 必須 | すべての要素 |

## 規則の詳細

### GH-PL-01　内側は1つのパッケージに置き、外部技術を読み込まない

| 項目 | 内容 |
|---|---|
| 水準 | 必須 |
| 適用範囲 | 内側 |
| 選んだ理由 | 読み込みの一覧が、依存の向きをそのまま表すため |
| 検証方法 | 内側のパッケージの読み込み一覧を見る |
| 違反の見つかり方 | そのファイルの先頭を読むと分かる |

### GH-PL-02　入口ごとにパッケージを分け、入口どうしは読み込まない

| 項目 | 内容 |
|---|---|
| 水準 | 必須 |
| 適用範囲 | 外側 |
| 選んだ理由 | 片方の入口を変えたときに、もう片方が巻き込まれる |
| 検証方法 | 入口のパッケージが、ほかの入口を読み込んでいないかを見る |
| 違反の見つかり方 | そのファイルの先頭を読むと分かる |

## 適用範囲外

- 依存の向きそのもの　→　構造の規約が持つ

## 委譲する判断

| 何を | どこへ | なぜ |
|---|---|---|
| 読み込みの並べ替え | 道具（宣言が選ぶ） | 道具が並べ替えるため |

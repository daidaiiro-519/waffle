Architecture Decision Record

図の宣言を、Document の内側の値として置く

図の宣言だけを別に確定させる場面が無く、外から識別子で指すこともできない。集約の条件を満たしていない。16の主張も、ブロックの集合を入れ替えないので種別ではない。

01決定

Waffle は、図の宣言を、Document の集約の内側にある再帰する値として置く。16の主張はその属性であり、種別ではない。欄の必須・禁止を守るのは schema ひとつとする。

決め手集約どうしは識別子で参照し合う。指せないものは集約ではない。図の宣言は documentId のように外から名指しできず、文書の中の位置でしか指せない。

02変更前と変更後

変わるのは図の宣言がどこに住むかである。記法そのものは、先立つ決定のまま変えない。

05付随して決めたこと

置き場所が決まると、守り手と表し方、そして動かす順が決まる。5点を同時に決めた。

論点決定
欄の必須・禁止を誰が守るかschema ひとつ。不変条件には「常に主張が定める組と一致する」の1行だけを書き、守り手を名指しする。判定するのは、その schema を引数に取る Document である
宣言は何を持たないか描いた結果を持たない。座標も配置も持たず、主張と中身だけを置く ── 導いた値を文書に持たない（承認済みの決定）が、図にもそのまま当たる
主張をどう表すか属性。ひとつの形に、主張をキーにした制約を掛ける。置くものの定義を16回複製しない
新しく作る文書2件だけ。16語と出典を置く knowledge と、宣言の形を検査する業務ユースケース
実装を動かす順語彙が先。描画の実装を層の外へ移すのは最後
それぞれの根拠を開く（5件）
論点根拠
宣言は何を持たないか座標を宣言に持つと、図を直すたびに古くなる。座標は解かせて数値だけ受け取ると既に決めているので、新しい制約ではなく、上位の決定に接続するだけである
欄の必須・禁止を誰が守るか16の主張と3つの欄の対応表を不変条件にも書くと、正本が2箇所になる。既にある不変条件12件のうち11件は守り手が schema なので、ここだけ例外にすると「不変条件」という言葉が2つの意味を持つ
主張をどう表すか種別にすると16個の形に分かれ、置くものの定義が16回複製されて同期の義務が残る
新しく作る文書実装だけあって仕様が無い検査を増やさないため。現に1件ある
実装を動かす順2つ目の描き先が無いまま口の形を決めると、ひとつの実装の都合を写すことになる

ADRのblock 03「変更前と変更後」— 器の具体イメージ

器はひとつ、中身は差し替わる

下はすべて同じ器で描いています。器のコードは1つで、中身が入れ子・操作と応答・並びに差し替わるだけです。

器が持つもの

持つもの役目知らないもの
面（変更前／変更後）2つ並べる中身が何であるか。入れ子か記録か並びかを器は知らない
枠（面の中に複数）場面や観点で区切る
面をまたぐ対応どれとどれが対応するかを示す
読みの一言その面から何を読み取るか

中身の3種

入れ子

実例あり — 関門1（業務領域の親が移る）

変更前

親は1つしか持てない

変更後

対応は参照が運ぶ

操作と応答

実例あり — 関門2（同じ操作で返るものが変わる）

変更前
check-spec-integrity
# 宣言を新しい置き場所へ書き換えたあと$ waffle check-spec-integrity --path …/bc-waffle.json{"declared_subdomains_missing_on_disk": [], "subdomain_ref_mismatches": []}↑ 古い場所を見て「違反なし」。書き換えが効いていない
変更後
check-spec-integrity
# 同じ操作$ waffle check-spec-integrity --path …/bc-waffle.json{"declared_subdomains_missing_on_disk":   ["sd-validation", "sd-reconciliation", …7件],  "usecase_files_missing_on_disk": [ …28件 ]}↑ 宣言された場所を見て、そこに無いと言う

並びと増減

実例なし。比較の表現としては正しいという判断で採用

2つ落として1つ足した

場面が2つあるとき — どちらの形にするか

関門2は場面を2つ持っています。器はどちらの形でも表せるので、読みやすい方を選びます。

案A

案A ── 1つの器が、場面を並べて持つ

変更前どうし・変更後どうしが縦に揃う。読みの一言は面ごとに1つ。

変更前
場面1 参照整合を確かめる
check-spec-integrity
# 宣言を新しい置き場所へ書き換えたあと$ waffle check-spec-integrity --path …/bc-waffle.json{"declared_subdomains_missing_on_disk": [], "subdomain_ref_mismatches": []}↑ 古い場所を見て「違反なし」。書き換えが効いていない
場面2 実装ファイルを保存する
保存時の応答
# src/waffle/… を保存（何も出ない）↑ 仕様を0件と判定し「対象外」として通した

止まらなかったことに、誰も気づけない

変更後
場面1 参照整合を確かめる
check-spec-integrity
# 同じ操作$ waffle check-spec-integrity --path …/bc-waffle.json{"declared_subdomains_missing_on_disk":   ["sd-validation", "sd-reconciliation", …7件],  "usecase_files_missing_on_disk": [ …28件 ]}↑ 宣言された場所を見て、そこに無いと言う
場面2 実装ファイルを保存する
保存時の応答
# src/waffle/… を保存✗ 実装の前に引き継ぎが要ります  仕様 28件 に対応する引き継ぎが見つかりません↑ 宣言から仕様を引いたので28件見つかる

引けなければ止まる

案B

案B ── 場面ごとに器を分ける

場面ごとに変更前と変更後が隣り合う。読みの一言は場面ごとに置ける。

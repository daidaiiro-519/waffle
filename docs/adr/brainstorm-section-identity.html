AI が引く節に、人が読む文書とは別の同一性が要るか

論点2（単位は読み手に従属する）の決着で、問いが変わった ── 「名前か印か」ではなく、節が文書とは別の同一性を持つかどうかになった。この論点が決まると、論点6（規則の置き場所）の前提も動く。

2反証を通過した案

案中身代償
A節に、変わらない印を持たせる機械が発番する印を鍵にする。人が読む射影では出さない節を手で書き足せない。印の重複と散逸を検査する責務が増える。印は意味を運ばない
B位置を同一性とし、動かすときは宣言する〈文書の識別子＋アドレス〉を鍵にし、改名・移動は移行の操作として書く宣言の書き忘れが観測できない。忘れたこと自体が、不在として現れない
C参照の側に、解決状態を持たせる鍵は名前のまま。指す先へ届いたかを、参照が申告する「移った」と「消えた」を区別できない。直し方は毎回、人が決める

3この選択が、段1と段2に置くもの

いま再定義しているのは段2 である。

段1　全型が継ぐ契約段2　8つの型
A印を持つ／採番と不変／参照は印を指す／射影で落とす　＝3つ増える増えない。既にある document への後付けの発番だけ
B移行の操作を動詞として固定。型が増えるほど太る各型が位置の安定を守る。アドレスが動くと、指す参照が全部書き換わる
C参照の語彙に、型と解決状態。同一性は増えない各型が、参照の欄で状態を申告する

4落とした案と、その理由

案落とした理由
×中身のハッシュを鍵にする中身を1文字直すと別物になる。エンティティの定義と衝突する
×外から指される節にだけ印を与える指す側は後から現れる。後で発番すると、それより前の突き合わせが切れる
×人が手で印を書く人が読む単位に機械の鍵が現れる。しかも手書きの印は重複する

5反証で分かったこと

  • 問いが「要るか」から「宣言で持つか、位置から導くか」へ変わった
  • 「要らない」に当たるのは C だけである。A と B は持ち方の違いにすぎない
  • C は A と両立する。排他なのは「指される側に同一性を置くか」だけで、「指す側が届いたかを申告するか」は別に決められる
  • JSON Schema に足りない6つのうち、「同一性」と「実体どうしの参照」は同じ1つの穴の両側である

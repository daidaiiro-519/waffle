部品ごとの描画結果

いま描ける14種と、図がこれからどうなるか

すべてその場で実際に描いた結果である。文字が主役の9種はいまの実装、図の5種はいまの実装（Mermaid）と新しい宣言で描いたもの（SVG）を並べる。

01全体の見取り

描ける部品は14種。うち図の5種は、承認済みの決定で主張の名前へ置き換わる。

群部品schema での使用これから
文字が主役paragraph 79 / table 68 / list 26 / section 22 / keyvalue 20 / code 11 / kvtable 7 / object 6計239回そのまま。段1 の語彙として定義する
未使用divider0回落とすかを決める
図graph 3 / sequence 2 / statediagram 1 / architecture 1 / flowchart 1計8回廃止。16の主張（関係7・量9）へ置き換わる
いま図の5種が抱えている問題を開く

描き方ごとに欄が生えている。flowchart は transitionsFrom、sequence は participantsFrom、graph は nodesFrom と groupsFrom、architecture は connectionsFrom——同じ「点と線」を描くのに、名前も欄も別々である。

新しい宣言では、書ける欄は items・links・frame の3つだけ。どれを書けるかは主張が決めるので、描き方ごとの欄は消える。

描いた結果（SVG・その場で描いたもの）
描いてみて分かったこと ── 2件

渡す例で、描き分けが見えたり見えなかったりする。ここで「階層」に渡したのは枝分かれのない一本道なので、「順序」と同じ絵に見える。枝分かれのある例を渡すと、木として描かれて明確に違う。描き分けを確かめるには、その主張が他と分かれる形の例を渡さなければならない。

図が単体では正しく描けなかった。出てくる SVG は class だけを持ち、色をページの CSS に頼っている。復元した実装の冒頭には「色と書体は要素の属性として持たせる。図だけを取り出しても正しく描け、機械で確かめられるようにするため」と書いてあるので、書いてある意図と実物が食い違っている。この一覧では属性を補って自己完結させた。

16の主張のうち、ここで見せているのは4つ

関係7（つながり・階層・包含・順序・循環・やり取り・対応）と量9（全体と部分・量の大小・順位・時間変化・分布・偏差・相関・流量・空間）で計16。復元した実装に描く手が揃っているのは、いまのところ太字の4つである。

残り12は recovered/figures/ に材料はあるが、src/ へ載せる作業がまだ済んでいない。

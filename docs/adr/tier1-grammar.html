03構造の文法 ── 6つ

中身を組み立てる語。どれも鍵と説明を持つという規律が掛かる。

部品何を組めるか成果物のどこへ落ちるか
値文字・数・真偽・時刻type が string／number／boolean、時刻は format: date-time
まとまり名前つきの欄の集まりtype: object ＋ properties ＋ additionalProperties: false
並び同じ形の繰り返し。各要素は鍵と説明を持つtype: array ＋ items。要素の properties に鍵と説明を置き、両方 required
入れ子まとまりの中のまとまり。深さは有界深さのぶんだけ展開する。$ref の再帰は使わない
選びある欄の値で、必須ブロックの集合が変わるallOf ＋ if（const で枝を指す）＋ then（required）。既定の枝は else
名前で共有同じ形を名前で何度でも使う$defs ＋ $ref
入れ子を展開する理由を開く

$ref の再帰を使うと、深さに限りが無くなる。「再帰は常に有界である」は既にある不変条件なので、深さのぶんだけ展開して、構造そのもので満たす。

実測では、いちばん深い型で15段。概念の木と図の入れ子がそれにあたる。

04値に掛かる修飾

独立した部品ではなく、文法に掛かるもの。既定値を足した。

修飾何を述べるか落ちる先
必須書かれていなければならないrequired
決め打ちこの値でなければならないconst
選択肢この中のどれかenum

閉じる宣言していない欄を許さないadditionalProperties: false

05標準の組み立て

文法だけでも組めるが、意味がどの型でも同じでなければ困るので、段1 が名前付きで持つ。

標準の組み立てなぜ段1 が持つか落ちる先
図16の主張と、主張ごとの必須と禁止が、どの型でも同じでなければ困る$defs に置き、主張ごとの必須・禁止を allOf ＋ if/then で書く
木2つの型が同じものを別々の名前で自前に組んでいた深さのぶんだけ展開したまとまりの入れ子

07落とすもの

説明が付かないまま残っていた語を、確かめたうえで落とす。

落とすもの理由
pattern一度も使われていない。1件と数えたのは、偶然そういう名前の欄だった
title / description成果物の側の語。宣言では、鍵と説明・読み方が同じ役目を果たす
maxItems ほか使われていない
pattern を1件と数えていた件

構造の語を数えたとき pattern が1回出た。中身を見たら「この概念の実現方針」という欄の名前だった。正規表現の pattern は一度も使われていない。

数えた語が、言語なのか欄の名前なのかを見分けていなかった。

論点 13

check.py は何を確かめるのか

問いが2つに割れた。「何を対象にするか」と「検査の根拠をどこに置くか」は別の問いで、片方だけ決めても、もう片方が空くと同じ腐り方をする ── 対象だけ決めれば根拠の無い検査が入り、根拠だけ決めれば原典にまで契約が伸びる。

1反証を通過した案

案中身代償
A対象だけを決める保守するもの（constraints ／ references ／ templates）に限る。検査の中身はその都度決める根拠が空くので、宣言の無い検査がまた入る
B根拠だけを決める検査は、宣言との照合だけで真偽が決まるものに限る。対象は限らない原典にも契約を課しうる ── 変えないものに契約を付けると SSOT が壊れる
C対象と根拠を、両方決める対象は保守するものに限り、内容は宣言との照合で真偽が決まるものに限る宣言の無い性質は、検査の前に宣言を足す工程が要る

5反証で分かったこと

  • 問いが2つに割れた ── 「何を対象にするか」と「検査の根拠をどこに置くか」。はじめは1つの問いのつもりで案を作っていた
  • いまの検査10件のうち、2件が宣言から導かれていない ── ID の重なり（規約のどこにも一意だと書かれていない）と、KINDS_BY_SHAPE の写しのずれ（自分で写しを作ってから、その写しを守っている）
  • 雛形と実物で、出典の表の1列目がずれている（雛形は「対象」、実物は「ID」）。いまの検査は節の見出ししか比べないので、これが見えない
  • 検査する側も同じ穴を持っていた ── figcheck.py は図がタプルでないと1件も検査せず、それでも「食い違いは無い」と出す。今回この盤面の図で実際に素通りした

6私の推し

C

対象と根拠を、両方決める。対象は「保守し続けるもの」に限り、検査の内容は「宣言との照合だけで真偽が決まるもの」に限る。検査を足すときは、どの文書のどの宣言を守るのかを先に書く ── 宣言が無いなら、検査ではなく宣言を先に足す。

なぜそう言えるか

結論のどこを支えるかもとにしたことその出どころ
対象を保守するものに限ること原典は SSOT なので保守しない。不要になれば消すだけである決まり利用者の判断（2026-09-06）
検査の内容を宣言から導くこと出典を持たない言明は規則ではない決まりSKILL.md ガードレール ／ references/sources.md
宣言の無い検査が実在すること「一意」「重複」で全文検索して0件。ID の重なりの検査だけが先に在る実測constraints/ ・ references/ ・ SKILL.md の全文検索（2026-09-06）
独自の解釈が原典と衝突しうることRH-TP-03「偽物を adapter へ置かない」は、Cockburn の an adapter to a "mock" database と逆だった原典alistair.cockburn.us/hexagonal-architecture/（2026-09-06 取得）
その場しのぎの対応を退けることエラーや不備を塞ぐ対応は、規約と knowledge から導く。その場で思いついた対応は、困りごとを消すだけで原因を残す決まり.waffle/documents/knowledge/knowledge-cand-avoidable-friction-is-not-detection

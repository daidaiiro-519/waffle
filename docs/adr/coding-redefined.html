Coding ／ 組み直し

規則が主、文書は束

いまの形からの差分ではなく、決まっていることだけから組み直した。 中心にあるのは規約でも層でもフォルダでもない ── 規則1件である。 規則が自分がいつ真かを持つので、写しが原理的に作れない。

何が在るか

規則が主。文書は承認のための束で、層とフォルダは導出である。 人とAIは、同じ文書を別の形で受け取る（論点2・論点8）。

① 規則 ── 自分がいつ真かを持つ

規則 1件
  言明        並行の単位は、所有を移して渡すものにする
  いつ真か    language = rust          ← 条件が空なら、どの場面でも真
  検証方法    共有した状態を跨ぐ書き込みが在るかを見る
  破れると    同じ値を2か所が書き、どちらが勝ったか誰にも言えない
  出どころ    原典 ／ 版 ／ 取得日 ／ 何を裏づけるか

これが写しを消す。「どの場面でも真」なら条件が空の規則が1件在るだけで、 用途ごとに書き写す先が無い。「Rust だから」なら条件は language=rust の1件で、 用途の文書がそれを持つことはない ── 条件が置き場所を決めるので、人が置き場所を選ばない。

② 文書 ── 同時に決まるものの束

文書 1本　＝　同じ人が、同時に決めるものの束
  題        Rust における失敗の運び方
  なぜ      失敗をどう運ぶかは、言語の仕組みで決まり方が変わる
  規則      4件（それぞれが自分の条件を持つ）
  範囲外    何を・どこが決めるか
  承認      誰が、いつ

文書が承認の単位である（論点7）── 規則1件ずつ承認するのは細かすぎ、
言語ぜんぶを1本にすると、1つ直すたびに全部を承認し直すことになる。

束ね方を決めるのは「一緒に決まるか」だけで、軸でも層でもない。 Rust の失敗の運び方を直すとき、Go の失敗の運び方は動かない ── だから別の文書。 逆に、失敗の運び方の4つの規則は一緒に決まるので同じ文書に入る。

③ 読むとき ── 3つの形

人が読むとき
  何を作るか（用途）→ どの言語で　の2問だけ答える
  出るのは1枚。その場面で真になる規則だけが、目録つきで並ぶ

AI が読むとき
  1枚にしない。必要な節だけを引く（「rust の失敗の運び方の規則」だけ）

層を見たいとき
  層は保存されていない。条件を数えれば出る
  ── 「language=rust だけを条件に持つ規則」＝ 言語だけで決まるもの

層もフォルダも保存しない。「言語だけで決まる規則」を見たければ、条件を数えれば出る ── 文脈の地図を保存せず描くのと同じ形である（論点19の決着）。

この組み方が消すもの

いまの形で悩んでいたことこの組み方では
フォルダを入れ子にするか、フラットにするか問いが消える。フォルダは層を表さない
用途の規約がアーキの層にも属する、をどう表すか問いが消える。規則が条件を持つので、属する層は数えれば出る
同じ言明を複数の場所へ書き写してしまう写す先が無い。条件が空なら規則は1件だけ在る
軸なしの規約をどこへ置くか置き場所は要らない。条件が空、というだけ
場面ごとに文書を作ると組み合わせが爆発する場面の文書は作らない。読むときに絞る

引き受けること

  • 規則1件ずつに条件を書く手間が増える。いまは文書ごとに1回書けば済んでいた
  • 条件の付け方を誤ると、集まらない。「どの場面でも真」のつもりで条件を付け忘れると、どこにも現れない
  • 人が読む1枚は毎回組み立てる。置いておけないので、読みたいときに出す手順が要る
  • まだ決めていない ── 条件に何を書けるか（軸の値だけか、範囲や否定も許すか）。ここは次の問いになる

02食い違いは、どこで生まれたか

3つとも決定と決定の間ではなく、決定と、その周りで書いたものの間で生まれている。

食い違いどこで生まれたかいま何が正しいか
語彙が7語だという前提6語→2語の測定から私が計算し、会話で一度言い、計画に書き写した決まっていない。承認済みの決定が定めているのは群の分け方と、足りない4つだけ。x-* の名前も数も射程外
決定と完成イメージが別の語彙段1／段2／段3 は完成イメージで生まれたが、そのあと書いた決定に持ち込まなかった決定は「集約」、完成イメージは「段」で語っている。同じことを2通りで言っている
コマンドの表と本文書き直したとき、表の2行だけ直して本文を見直さなかった本文は「読み方の指針は Schema の別のコマンドが返す」と書くが、表にそのコマンドが無い

03なぜ気づけなかったか

仕組みの側に2つ、進め方の側に2つ、原因がある。

起きた理由現れ方
決定に「置き換えられた」という状態が無いDocument には終端化があるのに、決定には無い。古くなった決定が承認済みのまま残り、どれが最新か分からない
書き直しを、同じ場所へ上書きしたコマンドの決定は Schema 3件 → 1件へ書き直したが、文書からは前の版が辿れない
新しい決定のあと、先立つ決定を読み返していない計画にその規律を書いておきながら、やっていない。食い違い3つとも、指摘されて初めて見つかった
計画を、題名と状態だけで立てた決定の本文を読み返していないので、決まっていないことを前提にした

04いま確かなこと

承認済みの決定が実際に定めていることだけを並べる。会話で言っただけのものは含めない。

決定定めていること定めていないこと
Schema を仕様から実装し、型は Document として置くJSON Schema は宣言から描かれる成果物になる／x-* は型に置き実体へ写さない／図は形が段1・値が Document語彙の名前と数
語彙を意味の名前だけにし、構造の部品と共通の欄を主張から分ける群を3つに分ける／文字の意味は4つ／図は主張8つ／足りない4つ／divider を落とすx-* をどうまとめ、どう名づけるか
コマンドを、判断に要るデータのある場所へ戻すSchema は骨格を作る／Document は5件／参照は持つが解決しないどの段の話か／読み方の指針を返す操作の扱い
図の宣言を、Document の内側の値として置く図の宣言は値オブジェクト／主張は属性であって種別ではない／守り手は schema ひとつ未承認

05次に決めること

計画を立て直す前に、決まっていない3つを先に決める。

決めることなぜ先か
x-* をまとめるか、どう名づけるか計画の第1手の中身そのもの。ここが決まらないと Schema の仕様が書けない
決定に「置き換えられた」を入れるか入れないと、今回と同じことがまた起きる
図の置き場所の決定を承認するかSchema の仕様に図の宣言が入るので、その入力になる

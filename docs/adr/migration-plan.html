04段1 だけは範囲を絞れない

型は5つに絞れる。段1 は絞れない。

なぜ段1 だけ違うのか

段2 は型ごとに独立しているので、5つだけ組み直しても残りは古い型のまま成り立つ。段1 は全型の共通契約なので、入れ替えると範囲外の37本が読めなくなる。

したがって第1段の条件は「新しい部品を用意する」だけでは足りない。旧い型を読んで判定・描画できたままにすることが要る。ただし旧い宣言を起こせる必要は無い ── 旧い型は既に型として在るので、起こす相手がいない（段1 の仕様 節07）。

これは後方互換を賄うことではなく、範囲を絞ると決めたことの代償である。

05状態は、実質ひとつの値しか取っていない

工程の4つの値のうち、実際に使われているのは2つだけである。

いまの値本数持っている型移した後

CREATED（工程）1同上範囲外（bc-artifact-share）
RENDERED（工程）0宣言だけある使われていない

RENDERED と SUPERSEDED は1本も無い。CREATED も1本だけで、それは範囲外にある。

つまり範囲内の44本はすべて VALIDATED 一色である。値ごとの対応表を作る必要が無く、落ちる情報も無い。

TemplateSchema の範囲が決まっていない17本のうち6本しか型を持たない。無いほうに template-judgment-platform・template-judgment-ux が含まれ、それは廃止して考え直すと決めた2領域である先に6本か17本かを決める。17本なら、その2本は後回しにできる

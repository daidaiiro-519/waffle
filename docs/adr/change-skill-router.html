一緒に呼ぶSkillを配線表から決めるrouter Skill：skill-router

目的

ある作業を1つのSkillだけでは終えられないとき、どのSkillを一緒に呼ぶかを配線表を見て決める際に使う。Orchestratorが作業の途中で必要な回数だけ呼び、呼んだSkillから返ってきた結果を、その作業への入力として渡す。配線表が持つのは「何を、誰に頼むか」だけで、「いつ呼ぶか（作業の前に材料を集めるのか、作業のあとに十分かを確かめるのか、両方か）」はOrchestratorが決める。skill-router自身はタイミングを持たない。

この文書が持つのは、配線表の読み方だけである。配線そのものは持たない。
配線はプロジェクトごとに違う。ここに書けば、書いたプロジェクトでしか使えないSkillになる。

どんなSkillを呼んでよいかも、この文書は決めない。それはプロジェクトごとの決め事なので、配線表のファイルに書く。

役割

- 1つのSkillだけでは終えられない作業を、外にある配線表を見て見分ける
- 何を頼むか・誰を呼ぶか・その相手が居ないときどうするかを返す
- 呼ぶSkillを、それぞれ独立した目的・役割・タスク・成果物・受け入れ基準を持たせて並列に呼び出せるよう、呼ぶSkillの名前の一覧を返す
- 作業側のSkillと呼ばれる側のSkillが互いを呼び合う形を避け、Orchestratorに代わって窓口になる
- ユーザーから配線の追加・修正・削除を頼まれたときは、対話しながら配線表のファイルを書き換える（判定だけを頼まれたときは書き換えない）

入力の想定

受け取る情報解釈・既定値
これから行う作業の名前明示されなければ、実行しようとしている内容から推測し、分からなければ呼び出し元に聞く。
その作業が何を対象にするか同じ作業でも対象によって呼ぶ相手が変わる場合は必須（対象ごとに配線表を引くため）。前の段階で実際に呼んだSkillがあれば、それも受け取る（固定リストではなく、そのつど引き継ぐ）。
配線表の場所明示されなければ、プロジェクト直下の skill-wiring.json を見る。無ければ配線が1件も無いものとして扱い、何も返さない（失敗にしない）。

配線表

配線表は、このSkillの外にある1つのファイルである。
形は references/skill-wiring.schema.json が決める。1行が4つの欄を持つ。

欄何を書くか
何を頼むか頼む内容。Skillの名前ではなく、してほしいことを書く（例:「認証まわりの安全性を見てもらう」）
どの作業のときその頼みごとが必要になる作業。同じ作業でも対象で変わるなら、対象まで書く
呼ぶSkill頼む相手のSkill名（複数可）
呼ぶSkillが無いとき作業を止める ／ 結果だけ渡す ／ 呼ばずに進む のいずれか

「呼ぶSkillが無いとき」に書ける3つの値。

値何が起きるか
作業を止める呼んだ相手の結果が返るまで、その作業を先へ進めない
結果だけ渡す結果は作業へ渡すが、作業は止めない
呼ばずに進む配線が無いことを咎めない。作業側が自分でできる範囲で進む

1行の例（このプロジェクトの配線ではなく、書き方を示すためのもの）。

{
  "何を頼むか": "認証まわりの安全性を見てもらう",
  "どの作業のとき": "code-review（認証・権限を含む変更）",
  "呼ぶSkill": ["security-advisor"],
  "呼ぶSkillが無いとき": "作業を止める"
}

ガードレール

- 配線の行を、この文書に書かない。行は配線表のファイルにだけ置く ── ここに書いた時点で、書いたプロジェクトでしか使えないSkillになる
- 呼んでよいSkillの種類を、この文書で限定しない。どのSkillを呼んでよいかはプロジェクトごとの決め事なので、配線表のファイルに書く
- 配線表に行が無い作業は、1つのSkillで終えられるものとして扱い、他のSkillを呼ばない
- 配線表が見つからないことを、失敗として扱わない。配線が1件も無いものとして進む ── 持ち出した先で必ず止まる作りにしない
- 「呼ぶSkillが無いとき」に書いた値が、そのまま振る舞いになる。作業を止める・結果だけ渡す・呼ばずに進む の3つ以外を書かない
- 1行だけに当てはまる例外を、この文書に書かない。前の段階から引き継ぐかどうかは、その行の「どの作業のとき」に書く
- skill-router自身は、作業側のSkillも呼ばれる側のSkillも、中で何をしているかを知らない。返すのは名前の一覧までで、並列呼び出しの組み立てと起動はOrchestratorが行う
- 配線表の行は「いつ呼ぶか」を持たない。同じ行を、1つの作業の中でOrchestratorが何度呼んでもよい。前用・後用の行を別々に作らない

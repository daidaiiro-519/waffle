実例 ／ rust × hook

Rust × Hook の置き場所

1つの場面を選ぶと、どのフォルダから何本が集まり、何が出るか。 実際に集める仕組みを走らせて、その結果で描いた ── 集まったのは15本。

緑　この場面で集まるもの 橙　注記と、新しく要るもの

そもそも、人は何から決めるか

先に来るのは「何を作るか」で、言語やアーキはその後である。 アーキと実行環境は用途が宣言しているので、人が答えるのは2問だけ ── SKILL.md 自身も「アーキテクチャは受け取らない。用途の規約が指定する」と書いている。 それなのに軸を4つ並べて説明しているので、複雑に見える。 そして言語を選ぶ材料は、規約32本のどこにも無い（「言語を選」「どの言語」で探して0本）── 人が最初に知りたいことに、いまの作りは答えられない。

フォルダ名は層（軸の値の組）。入れ子にしないのは、用途がアーキを決める形を入れ子で表せないため ── purpose.hook の規約は arch.hexagonal にも属する。属する層は文書の欄で宣言する。

② 出す ── 集めて1枚

$ waffle render-constraints --lang rust --purpose hook --out ./work

渡された軸
  language = rust        ← 自分で選ぶ
  purpose  = hook        ← 自分で選ぶ
  architecture = hexagonal      ← purpose.hook/stack が宣言
  runtime      = per-invocation ← 同上

./work/
└─ CONSTRAINTS.md     1枚だけ。15本を目録つきで連結（＋ common から1本 ＝ 16本）

自分で渡すのは言語と用途の2つだけ。アーキと実行環境は purpose.hook/stack が宣言しているので、 集める側が読み取る。実際に走らせた結果が上の15本（足りない規約 0本）。

目録が先頭に来て、そのあと規約の本文が順に続く。節の並びは種ごとに違う （規則を持つ種だけが「規則一覧」を持つ）。この形はいまの規約32本がすでに満たしているので、 中身の書き直しは要らない ── 変わるのは置き場所と、層を欄で宣言することだけ。

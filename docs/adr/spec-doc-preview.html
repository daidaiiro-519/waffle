01業務ユースケース ── 業務の層の1本

予約を確定する

種＝業務ユースケース　／　文脈＝予約　／　印 UC-01J7Q4K　／ 状態＝承認済み（差分あり）

概要

仮の予約を、席を確保した確定の予約に変える。

属する文脈

CTX-01H8ZZ2　予約

属する業務領域

SD-01H8Q3M　予約管理　（対応は宣言で持つ ── 入れ子ではない）

主アクターと意図

誰が何のために
予約した人席を確実に押さえる

事前条件

  • 仮の予約が在る（AGG-01H8V7C 予約）
  • その予約の期限が切れていない

基本フロー

  1. 予約を、印で取り出す
  2. 期限と席の空きを確かめる
  3. 予約を確定へ移す
  4. 確定したことを、外へ知らせる

事後条件

  • 予約が確定になっている
  • 席が確保されている

受け入れ基準

印〜のとき、〜となる
AC-01J7Q4K-1期限内で席が空いているとき、予約は確定になる
AC-01J7Q4K-2期限が切れているとき、確定にならず、期限切れとして返る
AC-01J7Q4K-3席が空いていないとき、確定にならず、空きなしとして返る

シナリオ

印分類本文確かめる単位覆う基準
SC-01J7Q4K-1正常 期限内で席が1つ空いている予約があるとき、確定すると、予約は確定になる 結合AC-01J7Q4K-1
SC-01J7Q4K-2異常 期限が切れた予約があるとき、確定すると、期限切れとして返る 単体AC-01J7Q4K-2

参照

指す先何を指すか
AGG-01H8V7C予約（集約）── 印で指す。値は写さない
VO-01H8W1D期限（値オブジェクト）

出す出来事

予約が確定した

この欄を持つかは決めていない ── 業務ユースケースの欄そのものは、この盤面では決めていない。

04承認のときに見えるもの

承認の境目（spec→実装）で人が見るのは、全文ではなく差分と、未検の一覧である（論点7 ・ 論点9）。

変わった節いまの値変えた理由
AC-01J7Q4K-3席が空いていないとき、確定にならず、空きなしとして返る 待ち行列を別のユースケースとして切り出した
UC-01J7Q4K事後条件に「席が確保されている」を足した 確保と確定を分けると、あいだで席が取られる
確かめたこと結果
参照が実在する節に届く違反 0
受け入れ基準を持たない操作が無い違反 0
シナリオと実装がずれていない違反 1　SC-01J7Q4K-2
題が振る舞いを述べている（人が見る）未検 2

承認したら、この差分は1つに畳まれて消える ── 残したい理由は ADR に書く（論点9 ・ 論点12）。

05この姿のうち、決まっていないもの

どこなぜ仮置きか

差し出しの約束の欄論点18 で下書きを書いただけ

出す出来事を持つか同上

決まっているのは、印で参照する ・ 受け入れ基準とシナリオが対で在る ・ 承認では差分と未検を見る ・ 指示は描画に出ない ・ 形は射影が決める ── この5つである。

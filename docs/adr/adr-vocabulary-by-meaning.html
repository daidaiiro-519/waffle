kvtable と keyvalue は、どちらも「1つのものの、名前と値の組」を描く。違うのは表にするか箇条にするかだけである。書き手に描き方を選ばせている。図についてだけ直したものが、文字の側に残っている。

01決定

Waffle は、描く語彙を意味の名前だけにする。構造の部品と共通の欄は、意味の部品から分けて置く。描き方は宣言から外し、意味と描き先から決まるようにする。

決め手同じ意味に名前が2つあるなら、それは描き方である。書き手が選んでいる以上、選ばれているのは意味ではない。kvtable と keyvalue、graph と flowchart が、どちらもその形になっている。

03理由

文字の側も図の側も、書き手に描き方を選ばせている。構造の部品と共通の欄が、意味の部品と同じ並びに置かれている。

測ったkvtable と keyvalue は、どちらも「1つのものの、名前と値の組」を描いている。違うのは表にするか箇条にするかだけである
図の側も同じだった
測った図の5種（flowchart・sequence・statediagram・architecture・graph）は Mermaid 由来の描き方の名前で、描き方ごとに違う欄が生えている
だから
言えること文字の側も図の側も、書き手に描き方を選ばせている。図についてだけ主張の名前へ移す決定を済ませたが、同じことが文字の側に残っている
並びを見ると
測ったsection と object は自分では何も描かない。object は入れ子の中を描くだけである。また from・heading・emptyText はどの部品にも付く
だから
言えること構造の部品と、共通の欄と、意味の部品が同じ並びに置かれている
分けて数え直すと
測った2つ足りない。変更前と変更後を並べる部品（いまは 対応 が肩代わり）と、読む必要の度合い。後者はのちに持たないと決着したので、いま足りないのはその部品の1つである
合わせると
結論語彙を意味の名前だけにし、構造の部品と共通の欄を主張から分ける。描き方は宣言から外し、意味と描き先から決まるようにする
なお
前提Markdown で描けることが語彙の下限になる。HTML の方が豊かに描けるが、それは同じ意味をより良く描けるということであって、HTML でしか言えない意味があるということではない
段の裏付けと、崩れるときを開く（5件）
段裏付けの種別参照先崩れるとき
kvtable と keyvalue が同じ意味実測描く実装の分岐を読んだ。一方は表の1行、他方は箇条として同じ組を描く—
図の5種が描き方の名前実測属性が transitionsFrom・participantsFrom・nodesFrom・connectionsFrom と描き方ごとに違う—
構造の部品が何も描かない実測object は入れ子の中を描くだけ、section は見出しを立てて each を描く—
2つ足りない実測変更前後の図が 対応 で書かれている実例と、この決定の折りたたみが宣言から出ていないこと—
Markdown が下限になるWaffle の設計判断knowledge に該当なしHTML でしか言えない意味が1つでも出てきたとき

最後の段だけ裏付けが実測でない理由 ── これは測って分かることではなく、どこを下限に置くかという選び方である。崩れるときも書いてある。

05付随して決めたこと

語彙を意味へ寄せると、いくつかの名前の行き先が決まる。3点を同時に決めた。

論点決定
対応 の2つの顔表の縦横が交わる主張だけに戻す。変更前と変更後を並べる役目は、別の部品として立てる
divider落とす。使用0で、区切り線は意味を持たない
描き先ごとの表現力の差描き手が吸収する。「裏付け」は HTML では折りたたんで、Markdown では小見出しで描く
それぞれの根拠を開く（3件）
論点根拠
対応 の2つの顔実例では、表の縦横が交わる主張（仕様の要素 × 実装で確かめるもの）と、図を2つ並べる部品（変更前 × 変更後）の両方に使われている。その部品の名前が無いので肩代わりしている
divider最新版の schema で使用0。描く実装には分岐があるが、宣言する相手がいない。区切り線は描き方であって意味ではない
描き先ごとの表現力の差折りたたみは意味ではなく描き方である。意味は「裏付け」「内訳」「根拠」で、この決定の折りたたみの見出しがそれを言っている。HTML が豊かなのは同じ意味をより良く描けるということであり、HTML でしか言えない意味があるということではない

06答えないこと

名前と欄の形は仕様で決める。この決定は群の分け方と、描き方を宣言から外すことだけを定める。

項目何が決まっていないかいつ決めるかどこで決まるか

卒制の後 ／ 設計メモ

文書のスキーマ層

作るのは新しいスキーマ言語でも、DBでもない。JSON Schema の上に、アドレスと射影と、宣言されたアクセスパターンを載せた層である。

「AI生成仕様の情報構造と実装対応」デッキのおまけ4枚を、道具の設計として詰めたもの。合意は8件、未決は2件。

01

決めたこと

論点決めたこと効く理由
軽量な新形式採らない上限18%。構造化出力を失う。削るのは渡す部分木のほう
新しいスキーマ言語採らない正本は完全な JSON Schema 1つ。足りないのは言語ではなく周りの規約
MD・HTML互換一方向の射影往復にすると文書が正本になり、構造まで推論に戻る
検索性宣言したアクセスパターン取得の単位を集約・不変条件・シナリオに揃える
DB要らない11,500ノードを17.6msで読み切る。規律だけ DynamoDB から採る
DDDプロファイルの1つ汎用層は仕組みだけを持ち、意味を1つも持たない
正本の置き場ファイル。索引は導出仕様はPRで読まれる。DBを正本にすると差分レビューが死ぬ
人が直す場所AIがJSONを直す場所を推論させない。中身の編集と構造の編集を分ける
いつ作るか卒制の後答えを持ったまま測ると、その答えが出るように測ってしまう

構造を完全に消しても、削れるのは34%が上限である。圧縮形式で取れるのはその半分にとどまる。日本語では中身が支配的だからである。

一方、アドレスで部分木を絞れば 634 → 数十 になる。同じ「トークン効率」でも、効き方が一桁違う。

03

層の形

汎用層は6つの原語で足りる

JSON Schema に足りないのは Shape 以外の5つで、それはスキーマ言語ではなく、その周りの規約とランタイムである。

Nodekind と id を持つ、アドレス可能な節
Address階層鍵。CTX#予約#AGG#予約#INV#01
Containmentどの kind がどの kind を含めるか
Shapekind ごとの中身の型。JSON Schema の $defs をそのまま使う
Projectionkind → MD / HTML の純関数
AccessPattern名前の付いた、アドレスと kind 上の問い合わせ

意味はプロファイルが持つ。ddd（仕様）、adr（決定）、research（章・正本・語彙・未決）。3つ目は、この研究のリポジトリ自身がすでにその形をしている。

汎用層に意見が無いなら、それは JSON Schema を作り直しただけである。価値はプロファイルの側にある。だからプロファイルは複数要る。

1本の鍵が、4つの役を持つ

使い道姿
ソートキーAGG#予約#INV#01
Markdown の見出しパス## 集約: 予約 › ### 不変条件 › INV-01
HTML の DOM パス<ddd-aggregate id=予約><ddd-invariant id=INV-01>
実装との突き合わせ@spec AGG#予約#INV#01

射影を一方向にしたから、これが成立する。往復可能にしていたら、文書側の編集で鍵が壊れる。

冪等の境界は、JSONにある

ただし JSON → MD の冪等は、ただでは手に入らない。3つ要る。

要るもの破れ方どうするか
正本の正規形鍵順・空白・数値表記が揺れると、意味が同じでも出力が変わる鍵順はスキーマの宣言順に固定する。整形はレンダラの前で1回だけ
不在と空の区別null ・ "" ・ キーが無い、の3つが同じに見えるrequired で決め、不在は不在のまま射影する
変換契約の版テンプレートを直せば、同じ JSON から違う MD が出る契約も版で固定し、出力に版を刻む

ここまでやると、射影後の MD をコミットして、その差分をレビューできる。JSON の差分は人が読めないが、MD の差分は読める。そして射影が冪等なので、両者は1対1で対応する。

未決の2件と、次に読むもの
未決なぜ決まらないか
アクセスパターンを列挙し切れるか宣言方式は、宣言していない問いに答えられない。DynamoDB が現場で嫌われる理由もそこにある。まず10個書き出して、答えられない問いを数える。
構造そのものを変えたいとき「不変条件を1件増やす」「集約を分割する」は中身の編集ではない。閉じた操作集合（add・move・delete）にして Containment で検める。ここで ADR が1件出る。

実装の前に台帳を作る先行事例 ── Markdoc（Stripe。Markdown ＋ スキーマ ＋ AST。ただし文書が正本で向きが逆）、JSON-LD ／ Schema.org、DITA、Astro Content Collections、TOON。「本文照合できていないものは根拠に使わない」を、ここにも当てる。

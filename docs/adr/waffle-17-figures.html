この検証が答えていること

Mermaidと同じ見た目を作ることが目的ではない。Mermaidが表せることは下限であって上限ではなく、SVGにCSSを当てられる以上そこは当然に届く、というのがこの検証の前提だった。確かめたのはその前提が本当に成り立つかである。

2つの描き方

点と線（7種）は Graphviz に座標と経路を解かせ、数値だけを受け取ってSVGを自前で組む。Graphvizの語彙（クラス名・DOT・SVG）は1つも越えてこない。図表（10種）はGraphvizを通さない。値から位置が一意に決まるので、算術だけで描ける。

この検証で分かった性質

正直に
難しかったのは何か

難しかったのはアルゴリズムではなく細部の数だった。方式が成立するかは早い段階で分かったが、そこから読める図にするまでに崩れを十数件直している。しかも同じ種類の失敗が繰り返し出た——CSSの重なり順、寸法の見積もり、単に描き忘れ。

方式の限界には一度も当たっていない。残っているのは作り込みの量であり、上限はMermaidではない。

「つながっていない」は目で見ても見落とし続けた。いまは記号の先端と線の端の距離と線の最後の一区間の向きを座標で照合する検査を置き、記号を7pxずらすと落ちることを確かめてある。目視の代わりではなく、目視が効かない種類の欠陥のために置いている。

ただし直し方には限界があった。目分量で形を調整している間は、何度直しても近づかない。実体と関連の図は3回「直した」と言って3回とも足りておらず、抜け出せたのはMermaidを手元で描かせてmarker の寸法と実体の大きさを実測し、数値で合わせてからである。見比べて直すのではなく、測って合わせる。

直したもの原因の種類
箱から文字がはみ出す寸法を見積もりで決めていた。書体の字幅表から実測するようにした
区画の文字が中央に寄るCSSの重なり順（.wf-node text が .wf-row に勝っていた）
辺の両端の記号が出ないマーカー任せをやめ、経路の向きから自分で描くようにした
ラベル同士が近い間隔の設定を渡していなかった
実行中の帯が無い単に未実装だった
開始・終了が空の箱になる役割ごとの形を持っていなかった
関連の記号が箱へ食い込む経路の向きのまま置いていた。着いた辺の外向きで置き直し、縁と平行に付くようにした
多重度が1つの記号しか無い多重度は「0か1か多か」と「必須か任意か」の合成。片方しか描いていなかった
「多」を3本の足で描いていた形の取り違え。Mermaidは先の尖った輪で描く。目分量をやめ、Mermaidを手元で描かせて marker の寸法を読み、6種すべてを実測に合わせた
実体が小さすぎて記号に負ける箱を文字の幅に詰めていた。実体は84pxの高さを持つ（Mermaidの実測値）。記号が大きい図では箱に最小の大きさを与える
記号と線がつながっていない記号は辺と平行、線は斜めに入る。別々の向きを向いていた。線の最後の一区間を辺の法線へ差し替え、継ぎ目は曲線で滑らかにした
型の図にER記法の輪が出る記法の取り違え。型と関連の多重度は記号ではなく文字で書く
記号に凡例が要るそもそも記号をやめた。カラス足も菱形も、覚えていない人には読めない。線の形をひねる必要も無くなり、経路が自然になった
同じ図で片方だけ曲がるGraphvizに辺の名前を渡していた。渡すと文字の箱を避けて経路がずれる（実測: 片方12px、もう片方0px。名前を外すと両方0px）。名前の位置はこちらで決めているので、渡すのをやめた
そのとき辺の名前が全部消えた名前の読み出し先を変え忘れた。線はきれいなままなので絵では気づけない。入力で名前を付けた辺が絵に出ているかを突き合わせる検査を足したところ、10件以上を検出した
辺の名前が日本語になっていない記号を語順のまま文字へ置き換え、読み返していなかった（「0か1つが1つに従う」）。数の向きも取り違えていた。矢印の向きに読んで文になる書き方へ直した
言葉に置き換えたら文字が増えた記号2つを言葉2つにしたので、1本の線に3つの文字が付いた。前より読みにくい。1本につき1つに畳んだ（「1つが0個以上を持つ」）。図の上の文字は6つから2つになった
概念の図が、決めたことと食い違う描画ではなく中身の誤り。業務領域を区切られた文脈の子として描いていた。外へ出すというのがこのADRの決定そのもので、図がそれを裏切っていた
注記が枠の線と重なる注記を1行ぶんの高さで数えていた。注記の行だけ厚くし、囲む枠を下へ伸ばした
流れ図が縦にしかならない向きを入力で受け取っていなかった
見た目の数値がCSSに直書き色・太さ・書体を名前付きの値へ出し、図のCSSから直値を無くした（残り0件）

点と線 ── pygraphviz（macOS / Linux / Windows すべてにバイナリ同梱ウィールが配布されており、システムへのインストールは不要）に座標を解かせ、矩形・経路・囲みの数値だけを受け取ってSVGを組み立てている。

図表 ── 外部の道具を使わない。軸・帯・割合・格子は値から位置が決まるため、その場の算術で描いている。

Markdown成果物は従来どおりMermaidのまま。この方式はHTMLで出すときにだけ使う。

見た目は--fig-*という名前付きの値だけで決まる。図を描くコードは色や太さを持たず、名前を参照する。明暗の切り替えは値の側で起きるため、図のコードは触らない。

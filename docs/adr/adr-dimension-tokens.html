寸法をトークンへ移す

コードに残っていた絶対値のpxをトークンへ移す。直ったのは矢じり1つで、残りは次の決定への地ならし。左右とも実際に描いたもの。

01書体を2.5倍にしたとき

変更前
箱と文字は大きくなったが、矢じりだけ小さいまま。head_len = 7が絶対値で、何にも比例していなかった
変更後
矢じりが線幅に比例して大きくなる。線幅は倍率^0.4で弱く追随し、最小1pxでクランプする

02実際に変わった量

見た目の印象ではなく、寸法を測って比べる。この変更で本当に変わったのは1つだけだった。
測ったもの変更前変更後
矢じりの長さ（等倍）7.07.2変わらない（正しい）
矢じりの長さ（2.5倍）7.0 のまま10.4これが直った
画布（間隔だけ詰めたとき）140×270135×2665pxだけ。ほぼ変わらない
「書体はそのままで間隔だけ詰める」は、変更前からできていた。間隔のトークンは元々独立していたので、この変更で得た能力ではない。変わったのは画布の余白が間隔に追随するようになった分（5px）だけで、能力の差ではなく程度の差である。

矢じりが倍率どおり2.5倍にならず1.5倍に留まるのは意図した挙動。矢じりは線の終端なので線幅に比例させ、線幅は倍率に弱く（^0.4）追随させて、細線が太線に化けるのを防いでいる。

03合否は、テストではなく静的な検査で言う

「テストが通った」は根拠にしない。コアを触らずに済むかは、依存の形で決まるので、数えられる条件にする。
条件変更前変更後
コアが持つ寸法の数値（係数を含む）12件6件
コアが参照する部品の種類名3件（box / frame / edge）3件（未着手）
部品を1つ足すのに要するコアの変更行数未測定未測定
残る6件は寸法ではなく、経路上の候補位置の割合（0.5・0.35…）と平方根。性質が違うので別に扱う。
下2行は手つかず。この変更だけでは「コアを触らなくてよい」とは言えない。

04この決定が含まないもの

切り出した先なぜ分けたか
尺度の体系（型・空間・線・形の4族＋全体倍率）絶対値pxを消すことと、尺度を作り直すことは別の決定。1つの案に束ねると、片方の理由でもう片方が正当化される
部品を名前で解決する仕組みコアがbox/frame/edgeを直に呼んでいる。ここが残る限り、部品を足すとコアが変わる
配置戦略の差し替え層状配置をコアに固定している。別の配置（力学配置等）が要るとアルゴリズムごと差し替えになる
辺が箱のどこに接続するかいまの契約は幅と高さしか申告しない。接続点を持たないので、コアが箱の形を推測している

05承認

未承認。2者の敵対的検証を経て、当初案（書体を唯一の基点にする）は破棄し、この範囲まで縮めた。

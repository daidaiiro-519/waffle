占有領域をひとつにする

描かれるものは全部、自分が占める領域を申告する。動かせるものが先に譲り、線は曲げない。実装して、同じ図の変更前と変更後を測った。

01この決定を入れた結果

「輪の一部」は帯が線を断って読める。A→B はまっすぐのまま。戻り線は囲みの外を通る。線は辺の中央を狙って出入りするので、矢じりは箱の外にあり、角の近くへ着かない。この図は、いまの実装で描いたもの。

変更前の絵は載せない。あれは直す前の実装が出した崩れで、いまのコードでは同じ絵を作れない ── 載せれば「古い実装の出力」を運び続けることになる。何が起きていたかは、下の実測で残す。

02何を変えたか

変更前障害物は、節点の箱だけ

網掛けが、経路と検査が「在る」と認識しているもの。囲みの札も辺の札も枠線も、描かれているのに存在しない。だから線はそこを平気で通る。

変更後描かれるものは、全部が領域を申告する

節点は自分の箱を、札は帯を、囲みは枠線を申告する。線は動かせないものだけをよけ、札のほうが線を避けて置かれる。種類を増やしても、集める場所は1つのまま。

変更前 ── compose.py
    # 端の2つ以外の箱は障害物。ぶつかるなら脇を回る。
    obstacles = [(coords[n][0], coords[n][1], ...) for n in coords if n not in (a, b)]
    # 札は経路が決まる前に置かれ、線とは突き合わせていない

変更後
    # 1. 動かせないもの（節点）だけを障害物にして、線を引く
    obstacles = [... 節点 ...]
    # 2. 動かせるもの（札）が、引かれた線を避けて場所を選ぶ
    label_x = 線に当たらない最初の位置          # 囲みの札
    place_edge_labels(..., occupied=札 + 枠線)  # 辺の札
    # 3. 避けられなければ、札を線より後に描く（帯が線を断って読める）
    body = 枠線 + 辺 + 札 + 節点

03占有領域は「動かせるか」を持つ

種類性質ぶつかったらどうするか
節点配置が決めた場所にある。動かせない線のほうが脇を回る
囲みの札・辺の札どこへ置いてもよい。動かせる札が場所を変える。変えられる場所が無ければ、帯を持っているので線の上に載る（線を断って読める）
囲みの枠線枠の位置は配置が決める。動かせない辺が跨ぐのは正常。ただし縁に沿って並走はしない（迂回の位置を囲みの外へ出す）。札はここを避ける

動かせるものと動かせないものを区別しないと、札を守るために線が犠牲になる。線は関係そのものを運ぶので、譲るのは常に札の側でよい。
もう1つ順序の規律が要る ── 接続点は、迂回で経路が変わった「後」に決め直す。曲げる前の向きで決めたままだと、横から来た線が底辺の中点へ刺さり、矢じりが箱へめり込む（実測で y=29.5、箱の内側）。
そして接続点は、相手の方向へそのまま引くのではなく、出す辺だけを相手の位置で決め、その辺の中央を狙う。方向へそのまま引くと角の近くへ着いて不自然になり、同じ節点へ集まる線もばらける。辺の中央を狙うと規則的になり、判定も1つ減る。（狙った先そのものではなく、そこにいちばん近い実際のインクへ着ける ── これは後の決定で足した。輪郭という中間物を経由すると、頂点を結んだ弦がインクの隙間をまたぐため）

04これで何ができるようになるか

できるようになる文字を描く部品を、安全に足せる

凡例・注釈・見出し・バッジ ── これまでは足すたびに、辺が貫くのに誰も気づかない状態が増えていた。これからは部品が領域と「動かせるか」を申告するだけでよい。

できるようになる量の図を、関係の図の節点として置ける

階層の中に円グラフ、対応の中に散布図。この決定の時点では円グラフ1つで破綻していた（矢印が空中に着き、名前が消えた）。その後、辺の着き先を描いたインクから選ぶ形にして解決した ── 11種×2通りの総当たりで崩れ0件。

これは解けないなぜ
絵が読みやすくなるわけではない詰まり・縦横比・配色は占有の問題ではない。目で見るしかない
札が線の上に載るのを避けきる枠が札より少しだけ広い場合、どこへ置いても線に当たる。そのときは載せる ── 帯があるので読める

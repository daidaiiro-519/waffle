Architecture Decision Record

Schema は3つの操作を持つ

承認済みの決定で JSON Schema が宣言から作られるものになった。ところが宣言から型を組み立てる操作が、どこにも無い ── 手続きでブロックを足していくだけである。

01決定

Waffle において、Schema は3つの操作を持つ ── 型を起こす（段2 の宣言から、型そのものを組み立てる）／骨格を作る（型から、段3 の実体の器を起こす）／読み方の指針を返す。Document の5つと、参照の規律は変えない。

決め手型を起こすことは、描くことでも骨格を作ることでもない。描くのは読み手向けの成果物へ落とすことで、JSON Schema は機械が使う型である。骨格を作るのは器を用意することで、型を起こすのは器の形そのものを組み立てることである。

022つの作り手

作られる側がまだ存在しないので、どちらも作り手が要る。違うのは、何を作るかである。

操作何を作るか入力誰の
型を起こす段2 の型そのもの（構造）段2 の宣言作り手
骨格を作る段3 の実体の器（値が空）。器と書き方の指針の両方を返す段2 の型＋識別子＋種別段2 のコマンド
読み方の指針を返すそのブロックを何のために読むか段2 の型＋ブロックの鍵段2 のコマンド

あの決定は一度、上書きで書き直している。その結果、前の版に何が書いてあったかが文書から辿れなくなり、食い違いを指摘されるまで気づかなかった。

今回は訂正ではなく不足の補いである。間違っていない決定を上書きすると、正しかった判断まで消える。だから古いほうを「置き換えられた」として残し、新しく作った。

取り下げとは別の状態である ── 取り下げは「誤っていた」、置き換えは「正しかったが範囲が足りなくなった」。

04理由

宣言から型を組み立てる操作が、どこにも無い。描くことでも骨格を作ることでもないので、名前を与える。

前提承認済みの決定で、JSON Schema は宣言から作られるものになった。段2 の型は Document として宣言され、そこから型が組み立てられる
だから
言えること宣言から型を組み立てる操作が要る。いまは存在しない ── patch-schema が「ブロックを足す」「枝を足す」と手続きで積み上げているだけである
これは描くことか、を確かめた
前提描くとは、読み手向けの成果物へ落とすことである。JSON Schema は人が読むものではなく、機械が使う型なので、同じ操作にはできない
骨格を作ることとも違う
言えること骨格を作るのは器を用意すること、型を起こすのは器の形そのものを組み立てること。前者を「骨格」と呼ぶのは自然だが、後者をそう呼ぶのは無理がある
持ち主を見ると
前提作られる側がまだ存在しないので、作り手が要る。骨格を作るときに使ったのと同じ理屈が、一段上でもう一度出る
表と本文の食い違いも見つかった
測った置き換えられた決定の本文に「読み方の指針は Schema の別のコマンドが返す」とあるが、コマンドの表にそのコマンドが無い
合わせると
結論Schema は3つの操作を持つ ── 型を起こす／骨格を作る／読み方の指針を返す。Document の5つと、参照の規律は変えない
段の裏付けと、崩れるときを開く（4件）
段裏付けの種別参照先崩れるとき
JSON Schema は宣言から作られる承認済みの決定Schema を仕様から実装し、型は Document として置く—
型を組み立てる操作が無い実測patch-schema の操作は add_block・rename_block・add_def・add_kind_branch ── すべて手続きで積み上げる形—
表と本文の食い違い実測置き換えられた決定の本文3か所と、コマンドの表—
作られる側が存在しないので作り手が要る確立された型DDD の作り手（Factory）作ったあとも作り手が相手を持ち続ける形になったとき

05付随して決めたこと

操作が増えると、名前と段の言い方が決まる。3点を同時に決めた。

論点決定
「骨格」という言葉器を用意することにだけ使う。型を起こすことは骨格と呼ばない
決定は、どの段の話かを言う「Schema」「Document」だけで書かない。置き換えられた決定は段を言っておらず、読むたびにどちらの顔の話か分からなくなった
読み方の指針を返すこと操作として表に載せる。本文だけにあって表に無い状態を解く
それぞれの根拠を開く（3件）
論点根拠
「骨格」という言葉骨格とは値を入れる器のことである。型を起こすのは器の形そのものを組み立てることなので、同じ言葉では指せない
決定は、どの段の話かを言う段2 は宣言としては Document、型としては Schema という二重の顔を持つ。段を言わないと、どちらの話か読み手が決められない
読み方の指針を返すことこの決定は「呼び出せる操作」を操作と呼ぶ（値を取り出す も数えている）。その定義なら、指針を返すことも同じ資格である

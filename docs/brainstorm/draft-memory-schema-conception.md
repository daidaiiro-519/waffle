schema が何を担うものかについて、2026-09-04〜05 のブレストで到達した点。**根拠の出どころで4つに分ける**——混ぜると、数えただけのものが「あるべき形の根拠」に化ける（この作業中に実際にやった。E を参照）。

記録: `https://claude.ai/code/artifact/855ec252-fea7-4830-88cd-05f7a47cde5d`（図7枚。見解が変わった箇所は押すと変更前と理由が開く）

## A. 合意した原理

- **三層は抽象と具体ではなく、メタレベルである。** `abstract schema` が `concrete schema` を縛り、`concrete schema` が文書エンティティを縛る。**`concrete schema` は `abstract schema` のインスタンスであり、同時に文書の型でもある。** この二重の役が核心で、JSON Schema 自身が meta-schema を持つのと同じ形。厚い／薄いという責務の配分の話ではない
- **「値だけを推論させる」は再帰する。** `concrete schema` を書く行為そのものが構造の推論であり、それを縛るのが `abstract schema`。**これが段1の存在理由。** 共通部分をくくり出したのではなく、同じ原理をもう1段上に当てている
- **単位は読み手に従属する。** 人間は認知に形式を要求する（ビジュアライズされていないと読めない）→ MD/HTML → 単位は文書。AI は形式を問わない（何を渡しても自然言語として処理する）→ 要るのは構造の明示と読み方 → 単位は節。**検証・状態・承認は人間が読むので文書単位、取得・参照は AI が行うので節単位**。「文書かグラフか」は偽の二択で、「単位」という語が4つの別物（人が読む／検証と状態／取得と参照／保存）を指していた
- **構造は意味的空間だが、命名が守られているときだけである。** 構造は型を保証し、意味は保証しない。`invariants[]` に不変条件でないものが書かれても検証は通る。`items` のように名前が意味を運ばない鍵では自明性が消える。**だから書き方の指示とセットで初めて意味的空間になる。** そして意味は検証できないので、最後に人の承認が残る——Human On The Loop が消えない理由
- **構造化の利得は「無いことが分かる」ことである。** grep は「見つからなかった」と「無い」を区別できない。構造で引けば「その欄が空である」と言い切れる。不在が観測できる
- **取得は冪等でありうる。** プロンプトは意図しか運べず、スキーマは手段を運べる。grep→周辺から推論→横断のループは毎回違う経路を通り、同じ問いに同じ範囲が返らない。**スキーマは両端（取得・射影）を縛れるが、真ん中（推論）には届かない。取得が揺れると推論の入力が毎回変わるので、値の揺れはその手前で増幅されている**
- **JSON Schema に足りないのは6つ。** 同一性／書き方の指示／操作／射影／**実体どうしの参照**／版と移行。とくに `$ref` は型の再利用であって、インスタンス間の参照ではない

## B. 数えたもの（問題が実在することの証拠。あるべき形の根拠には使わない）

- AI生成仕様 628本・アンカー 1,205件（`spec-correspondence/02-dataset`）: **50%の仕様が参照を出す**（中央値2・最大35）／**89%がバッククォートで囲んだ裸のパス**／**33%が解決しない**（未解決13.7・外部18.3・曖昧1.3）／参照先の主体は実装ファイル（`.go` 288・拡張子なし317・`.md` 145）
- 同 628本の見出しは **h4 で止まる**（h4 9,873・h5 12）
- 原型での実測: 節を別の親へ移すと、名前を鍵にした差分は `removed 1 / added 1`（同じものが消えて増えたと言う）。**不変の印を鍵にすると `moved 1` になり、突き合わせの件数が前後で1件も変わらない**。スキーマの版を上げても同じ
- 形式ごとのトークン（同一の仕様片）: JSON 634 ／ MD 593 ／ YAML 586 ／ 表形式 522 ／ **中身の文字列だけ 416**。**構造を全部消しても削減は34%が上限**

## C. まだ論点

- **論点3（同一性）**——論点2の決着で問いが変わった。「名前か印か」ではなく、**「AI が引く節に、人が読む文書とは別の同一性が要るか」**。文書には同一性がある（パス・ID）。節にも要るのかが問い
- **論点6（規則の置き場所）**——`abstract schema` がクエリとコマンドを固定すると、`concrete` 固有の規則の行き場が問題になる。コマンドとして足せば型が増えるたび `abstract` が太り、宣言として持てば `abstract` に「何が違反かを書く語彙」が要る。**宣言で書ける規則と、走査・構文解析・循環検出のような能力を要する検査の線をどこに引くかが、この論点の実体**
- **書く単位と承認する単位のずれ**——AI は読み手であると同時に書き手である。書く単位は節（欄を埋める）、承認する単位は文書（人が1本として読む）。「どこまで書いたら人に見せるか」は節の数では決まらず、文書が閉じたときに決まる。**このずれが Human On The Loop の境界そのもの**

## D. 私の提案（未採用・要判断）

- 節に**不変の印**を持たせ、突き合わせの鍵をそこへ移す。名前を鍵にすると2方向に間違える（改名で偽陽性、中身の入れ替えで偽陰性）
- **版の移行**を、閉じた操作集合の宣言として持つ。いまは版のずれを検知するところまで
- **参照に型と解決状態**を持たせる（実体を指す／実装を指す／外部を指す、および「確認ない」という第3の状態）
- `abstract schema` に**「何が違反かを書く語彙」**を置く（論点6を宣言側で閉じる場合）

## E. この作業で踏んだ既存メモリ

`feedback_redefinition_does_not_reason_from_the_existing` を実際に踏んだ。現行の実装（クエリの動詞の数・検査の行数・式言語の選択）の形から「足せるのは印1つだけ」「規則の語彙は要らない」と結論し、5往復ぶん取り下げた。**既存メモリが効いた事例であって、新しい feedback は立てない。**

なお B に置いた実測は、同じメモリが許している「問題が実在することの証拠」としてだけ使っている。**A の原理は、どれも既存実装から導いていない。**

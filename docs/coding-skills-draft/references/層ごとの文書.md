# 層ごとの規約 ── どの層に、どの規約を置くか

## 概要

**層ごとに、決められることが違う。**
だから置く規約も層ごとに違い、**同じ4種別をすべての層へ並べない**。

## 決められること／決められないこと

| 層 | 決められる | 決められない |
|---|---|---|
| 言語 | 綴りと書式、失敗の運び方、並行の単位、テストが走る仕組み、標準の道具 | どんな層があるか（アーキテクチャが決める）／何を保証するか（用途が決める） |
| アーキテクチャ | 層の名前、依存の向き、層ごとの責務 | それを何で表すか（言語が決める） |
| 言語 × アーキテクチャ | 層を何で表すか、向きを何で守るか、テストの置き場所 | 何を保証するか（用途が決める） |
| 用途 | 外との契約、起動と終了、保証する振る舞い、採るアーキテクチャ、採る道具 | ── ここが可変で、上の3層が空けた穴を埋める |

## 置く規約

| 層 | 規約 | その規約が決めること |
|---|---|---|
| `lang.<言語>` | `style.md` | 綴りと書式 |
| | `failure.md` | 失敗の運び方 |
| | `test-mechanism.md` | テストが走る仕組みと、書き方 |
| | `toolchain.md` | 標準の道具と、その版 |
| `arch.<様式>` | `layers.md` | 層の名前と、層ごとの責務 |
| | `dependency.md` | 依存の向き |
| `lang.<言語>+arch.<様式>` | `layer-mapping.md` | 層を何で表し、向きを何で守るか |
| | `test-placement.md` | テストをどこに置くか |
| `purpose.<用途>` | `contract.md` | 外との契約 |
| | `lifecycle.md` | 起動と終了 |
| | `acceptance.md` | 何を保証するか |
| | `stack.md` | 採るアーキテクチャと道具 |

## 種別

**種別（コーディング／テスト／アーキテクチャ／技術スタック）は、置き場所ではなく欄である。**
横断で引くための分類なので、制約1件ごとに宣言する。

| 引きたいこと | どう引くか |
|---|---|
| この場面に効く制約を全部 | 軸の値で集める |
| テストに関わる制約を全部 | 種別の欄で絞る |

## 空のマス

**その層で決まらないことの規約は、作らない。**
言語の層に「層と依存の向き」は無いので、`lang.go/dependency.md` は置かない。

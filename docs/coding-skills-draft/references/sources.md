# 出典 ── 規則は、何を根拠に書けるか

## 概要

**出典を書けない規則は、規則として置けない。**
「誰かがそう決めた」しか言えないものは、他のプロジェクトへ持って行けない。

## 認める出典

| 種類 | 何を指すか | 添えるもの |
|---|---|---|
| 規格 | 言語仕様、RFC、プロトコルの仕様 | 版と、原文で照合する文字列 |
| 原典 | 公式ガイド、公式リファレンス、確立した文献 | 落とした日と、原文で照合する文字列 |
| 実測 | 自分で数えた記録 | 測った対象、件数、測った日 |

## 認めない出典

| 種類 | なぜ認めないか |
|---|---|
| このプロジェクトの決めごと | 場面が変われば成り立たない** ── 入れた時点で、どの場面でも同じ答えを返すという前提が壊れる** |
| 要約されたもの | 言い換えた時点で、原典とは別のものになる |
| 出典を持たない経験則 | 正しいかもしれないが、確かめる先が無い |

## 照合の仕方

| 手順 | 内容 |
|---|---|
| 1 | 原文を落とし、落とした日と `sha256` を残す |
| 2 | 規則が使う識別子を、**原文の文字列でそのまま照合する** |
| 3 | 照合できなかった識別子は、原典の名前として書かない |

**URL だけでは足りない。**
指す先に届いているかを、誰も確かめられないためである。

## 版が変わったとき

**「公式」であることは、正しさを保証しない。**
版が上がったら、照合する文字列がまだ原文に在るかを確かめる。
無ければ、その規則は出典を失っている。

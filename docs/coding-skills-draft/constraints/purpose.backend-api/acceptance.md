# バックエンドAPI が保証する振る舞い

## 概要

**呼び出し元から見た状態コード・応答の形・再送時の扱いを保証し、内部の作りは保証しない。**

## 保証する振る舞い

| ID | 振る舞い | 検証の単位 | 前提条件 | 失敗したときの現れ方 |
|---|---|---|---|---|
| BA-AC-01 | 契約どおりの要求に、契約どおりの状態コードと応答を返す | 端から端まで | 依存が動いている | 状態コードか応答の形が違う |
| BA-AC-02 | 契約に合わない要求は 400 で返し、どの欄が問題かを示す | 結合 | ─ | 500 になる、または欄が示されない |
| BA-AC-03 | 同じ要求識別子での再送は、二重に反映されない | 端から端まで | 要求識別子を受け取る | 2度反映される |
| BA-AC-04 | 依存が失敗しても、内部の詳細を応答へ出さない | 結合 | 依存の失敗を作れる | 内部の詳細が応答に出る |
| BA-AC-05 | 停止の合図を受けても、処理中の要求は最後まで返る | 端から端まで | 停止を起こせる | 処理中が打ち切られる |

## 保証しない振る舞い

| 何を | 保証しない理由 | 代わりに何で担保するか |
|---|---|---|
| 応答の速さ | 環境で変わる | 運用での計測（この規約の外） |
| 内部のパッケージ構成 | 呼び出し元から観測できない | 層の規約と依存の検査 |
| 依存の実物の振る舞い | 依存の版で変わる | 契約のテスト |

## 振る舞いの詳細

### BA-AC-03　同じ要求識別子での再送は、二重に反映されない

| 項目 | 内容 |
|---|---|
| 前提 | 呼び出し元が要求識別子を付ける |
| 入力 | 同じ識別子の要求を2回送る |
| 期待する結果 | 反映は1回。2回目は1回目と同じ応答を返す |
| 検証の単位 | 端から端まで |
| 実行コマンド | `go test -run TestIdempotency ./...` |
| 失敗の切り分け | 2度反映されるなら、識別子の記録が効いていない |

### BA-AC-05　停止の合図を受けても、処理中の要求は最後まで返る

| 項目 | 内容 |
|---|---|
| 前提 | 停止の合図を送れる |
| 入力 | 処理中に `SIGTERM` を送る |
| 期待する結果 | 処理中の要求は完了し、新しい要求は断られる |
| 検証の単位 | 端から端まで |
| 実行コマンド | `go test -run TestGracefulShutdown ./...` |
| 失敗の切り分け | 打ち切られるなら、受け付けの停止と待機の順が逆 |

## テストの構成

| 種類 | 対象 | 置き場所 | 実行の速さ |
|---|---|---|---|
| 単体 | 業務モデル・業務操作 | 同じパッケージ | 1件あたり数ミリ秒 |
| 結合 | 入力アダプタ・出力アダプタ | 外部パッケージ | 1件あたり数十ミリ秒 |
| 端から端まで | 起動した実行ファイル | `test/e2e` | 1件あたり1秒以内 |

## 適用範囲外

| 何を | どの層が決めるか |
|---|---|
| 確かめる単位の境界 | アーキテクチャ |
| テストが走る仕組み | 言語 |

## 委譲する判断

| 委譲する判断 | 委譲先 | 委譲する理由 |
|---|---|---|
| 依存を実物で確かめるか、代役で確かめるか | 実装 | 用意できる環境で決まる |

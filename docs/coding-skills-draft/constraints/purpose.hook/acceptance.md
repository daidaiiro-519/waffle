# Hook が保証する振る舞い

## 概要

**呼び出し元から見た入出力と終了コードを保証し、内部の作りは保証しない。**

## 保証する振る舞い

| ID | 振る舞い | 検証の単位 | 前提条件 | 失敗したときの現れ方 |
|---|---|---|---|---|
| HK-AC-01 | 正しい要求に対し、1行の JSON と終了コード `0` を返す | 端から端まで | 実行ファイルが作られている | 応答が複数行になる、または終了コードが `0` にならない |
| HK-AC-02 | 壊れた要求に対し、終了コード `1` と、原因を示す診断を返す | 端から端まで | 同上 | 終了コードが `0` になる、または診断が空になる |
| HK-AC-03 | 標準出力へ応答以外を書かない | 端から端まで | 同上 | 呼び出し元の解釈が失敗する |
| HK-AC-04 | 1 MiB を超える要求を、内部の失敗ではなく要求の不備として扱う | 端から端まで | 同上 | 終了コードが `2` になる |
| HK-AC-05 | 同じ要求を2度渡すと、同じ応答が返る | 端から端まで | 状態を持ち越さない | 2度目の応答が変わる |

## 保証しない振る舞い

| 何を | 保証しない理由 | 代わりに何で担保するか |
|---|---|---|
| 内部のモジュール構成 | 呼び出し元から観測できない | 層の規約と依存の検査 |
| 応答の生成に要した時間 | 呼び出し元の仕様が定めていない | 起動の規約（100 ms 以内に書き始める） |
| 診断の文面 | 変わりうる | 診断が空でないことだけを確かめる |

## 振る舞いの詳細

### HK-AC-01　正しい要求に対し、1行の JSON と終了コード `0` を返す

| 項目 | 内容 |
|---|---|
| 前提 | 実行ファイルが作られている |
| 入力 | 標準入力へ、契約どおりの1行の JSON |
| 期待する結果 | 標準出力が1行の JSON、終了コードが `0` |
| 検証の単位 | 端から端まで |
| 実行コマンド | `cargo test --test hook_stdio` |
| 失敗の切り分け | 応答が複数行なら、診断が標準出力へ混ざっている |

### HK-AC-05　同じ要求を2度渡すと、同じ応答が返る

| 項目 | 内容 |
|---|---|
| 前提 | 呼び出しごとに終了し、状態を持ち越さない |
| 入力 | 同じ要求を、2つのプロセスへ順に渡す |
| 期待する結果 | 2つの応答が一致する |
| 検証の単位 | 端から端まで |
| 実行コマンド | `cargo test --test hook_stdio idempotent` |
| 失敗の切り分け | 一致しないなら、一時ファイルか環境の状態が残っている |

## テストの構成

| 種類 | 対象 | 置き場所 | 実行の速さ |
|---|---|---|---|
| 端から端まで | 実行ファイルの入出力 | `tests/hook_stdio.rs` | 1件あたり100 ms 以内 |
| 結合 | 入力アダプタと業務操作 | `tests/` | 1件あたり数十ミリ秒 |

## 適用範囲外

| 何を | どの層が決めるか |
|---|---|
| テストが走る仕組み | 言語 |
| テストの置き場所の規則 | 言語 × アーキテクチャ |

| 委譲する判断 | 委譲先 | 委譲する理由 |
|---|---|---|
| 性質テストで入力を広げるか | 実装 | 要求の形の幅で決まる |

# AI活用ワークショップのアンケート・効果測定案

個人のAI活用の変化と、他者が実務で使える成果物を報告の主軸にする。段階評価による自己申告、具体的な行動の説明、他者の試用記録を組み合わせる。人気投票は共有会の表彰として扱う。

本書は主催者がフォームへ転記するための設問案である。オンラインフォームの作成・配信は行っていない。回答の所要時間は8分を目安にし、開始前に少人数で試して設問量を調整する。この設問と尺度は今回の企画に合わせて作ったもので、妥当性を検証済みの標準尺度ではない。

## 実施時点と回答の扱い

| 項目 | 設計案 |
|---|---|
| 事前 | 教材の視聴・演習を始める前に回答する |
| 中間 | 中間発表後に回答する。支援内容の改善にも使う |
| 終了時 | 最終共有会後の試用期間を終えてから回答する |
| 個人の対応付け | 主催者が発行した同じ参加者IDで3回を対応付ける |
| 冒頭の属性 | 参加者ID、時点、現在の職種（開発／PM／PL／その他）、職種変更の有無 |
| 必須と任意 | 共通・職種別の選択項目を基本とする。自由記述は短文とし、回答しにくい内容は省略できる |
| 利用目的 | ワークショップの改善と成果報告。人事評価には使わない運用を提案する |
| 共有範囲 | 個別回答は主催者が確認し、部長向けには集計を示す。事例の引用は本人に確認する |

IDで対応付けるため、完全匿名とは案内しない。15名程度では職種や記述から本人が推測される可能性もあるため、少人数の職種別内訳を必要以上に公開しない。

## 全員が回答する共通項目

設問の文言と尺度は3回とも固定する。現在の状態を回答してもらい、終了時に事前の回答を上書きしない。

| ID | 設問 | 回答形式 |
|---|---|---|
| F1 | 過去4週間に、実務でAIを使った日は何日ありましたか。研修の演習だけに使った日は含めません。 | 0日／1〜3日／4〜7日／8〜15日／16日以上／実務の機会なし |
| C1 | AIを使えそうな仕事を思いつけますか。 | 能力尺度C |
| C2 | 仕事で困っている理由を整理できますか。 | 能力尺度C |
| C3 | AIに、してほしいことを伝えられますか。 | 能力尺度C |
| C4 | AIに、いくつかの作業をまとめて頼めますか。 | 能力尺度C |
| C5 | 作ったものの使い方を、他の人にも分かるように説明できますか。 | 能力尺度C |
| C6 | AIの答えが間違っていないか確かめられますか。 | 能力尺度C |
| C7 | 他の人からの感想をもとに、作ったものを直せますか。 | 能力尺度C |

F1には任意の補足欄を付ける。休暇、業務変更、利用制限など、活用機会が変わった事情を記録できるようにする。

### 能力尺度C

| 値 | 参加者に表示する選択肢 |
|---|---|
| 0 | まだやり方が分からない |
| 1 | やり方は分かるが、まだできない |
| 2 | 手助けがあればできる |
| 3 | 一人でできる |
| 4 | 状況に合わせてやり方を変えられる |
| 対象外 | 試す機会がない |

対象外は0点に変換しない。本人の感覚による回答なので、客観的な習熟度として断定しない。中間・終了時の自由記述で、できると判断した根拠を一つ挙げてもらう。

## 職種別の業務項目

担当する業務について、AIをどの程度使っているかを回答してもらう。PMとPLの担当範囲は組織によって異なるため、職位だけで全項目の経験を前提にしない。兼務者は両方の表から実際に担当する項目を選ぶ。

### 業務活用尺度B

| 値 | 参加者に表示する選択肢 |
|---|---|
| 0 | 使い方が分からない |
| 1 | 使えそうだが、まだ試していない |
| 2 | 試したが、仕事では使っていない |
| 3 | 仕事で使った |
| 4 | 仕事で繰り返し使っている |
| 対象外 | 担当していない、または試す機会がない |

段階2は試用までで、仕事にはまだ使っていない状態。段階3・4は、AIの答えを確かめて仕事で使った場合に選ぶ。

### PM・PL向け

| ID | 設問：次の業務で、現在AIをどの程度使っていますか。 | この項目で見たい悩み |
|---|---|---|
| P1 | 資料に使う情報を集める | 材料集めに時間がかかる、比較の観点が分からない |
| P2 | 会議で決まったことをまとめる | 要約は作れても、次に誰が何をするか分からない |
| P3 | 関係者の意見の違いを整理する | 立場の違いを伝えられない、合意した内容がずれる |
| P4 | 仕事の遅れや困りごとを見つける | 状況を集める負担が大きい、遅れの兆候に気づけない |
| P5 | メンバーに聞くことを考える | 困りごとを引き出せない、何を支援すべきか整理できない |
| P6 | 仕事の手順を他の人に伝える | 記録しても使われない、引き継ぎの説明を繰り返している |

P3・P5では、人の気持ちや能力をAIに断定させることを到達目標にしない。本人への確認や対話の準備にAIを使えるかを確かめる。P1は日常業務の活用状況を聞く項目であり、ワークショップの制作課題を顧客提案に限定するものではない。

### 開発者向け

| ID | 設問：次の業務で、現在AIをどの程度使っていますか。 |
|---|---|
| D1 | 要求を整理し、仕様や設計の選択肢を比較する |
| D2 | コードを作成・修正し、動作と制約への適合を確認する |
| D3 | テストを設計・実行し、不具合の原因を調べる |
| D4 | コードや設計をレビューし、指摘の根拠を確かめる |
| D5 | 開発の反復作業を、エージェントやSkillsで仕組みにする |
| D6 | 既存のコードや開発手順を理解し、他者に引き継ぐ |

## 困りごとと学びたいこと

| ID | 設問 | 回答形式 |
|---|---|---|
| N1 | 今、AI活用で特に困っていることを選んでください。 | 下の選択肢から最大3つ。困りごとなし・その他も用意 |
| N2 | 今後、AIを使ってできるようになりたい業務を選んでください。 | 自分が回答したP／D項目から最大2つ。その他・まだ思いつかないも用意 |
| N3 | その業務の、どんな場面で困っていますか。 | 一つの場面を短文で記入。具体的な案件名は不要 |
| N4 | どの支援があると、次に進めそうですか。 | 考え方を学ぶ動画／操作の説明／使い方のヒント／ブログ／Teams投稿での相談／会話での相談／使うツールの準備／学習時間／その他。最大2つ |

| N1の選択肢 | |
|---|---|
| 発想 | 何ができるか分からない／自分の仕事への使いどころが思いつかない |
| 依頼 | 必要な情報を整理できない／何をどこまで任せるか決められない |
| 出力 | 正しいか判断できない／確認や修正に時間がかかる |
| 再利用 | 案件が変わると使えない／他者に使い方を説明できない |
| 環境 | 情報を入力できる範囲が分からない／ツール・権限・利用枠が不足している |
| 継続 | 試す時間がない／相談する相手や方法が分からない |

N1は個々の選択肢を一つずつ表示する。「発想」などの分類名は主催者の整理用とする。PM・PLの悩みはこの時点では仮説であり、事前回答で確認して教材や相談会の話題に反映する。

## 時点別の短い自由記述

| 時点 | 設問 |
|---|---|
| 事前 | AIを使っている、または使ってみたい仕事を一つ挙げてください。今はどのように進めていますか。 |
| 中間・終了時 | 新しくできるようになったこと、または試したがうまくいかなかったことを一つ挙げてください。入力した情報・出力・確認や修正の方法を教えてください。 |
| 中間・終了時 | その変化に影響したものは何ですか。教材、相談、実務経験、他の研修、ツールの更新などから教えてください。 |
| 終了時 | 今後も実務で使いたいものと、まだ支援が必要なことを教えてください。 |

変化なし・未実施・悪化もそのまま回答できるようにする。改善した話だけを選ばせない。

## 他者が使える成果物の記録

作者の成果物説明と、利用者の試用記録を組にして残す。

| 作者が示す内容 | 利用者が確かめること |
|---|---|
| 達成する目的、対象業務、対象外の用途 | 自分の業務に合う用途か |
| 使うための条件と、公開された説明 | 作者だけが知る前提やコツが必要にならないか |
| 仕組みからの案内や確認 | 作者への質問なしで、必要な操作や判断が分かるか |
| 環境、実行方法、期待する結果 | 提供された説明と仕組みだけで、目的を達成できるか |
| 分かっている限界 | どこを人が確認・修正する必要があるか |

利用者は、使用日・成果物ID・利用目的・提供された説明・結果・作者への質問が必要だった点・次に直してほしい点を記録する。機密情報の本文は記録しない。

結果は「未試用／作者の補足なしで目的を達成／作者の補足を受けて目的を達成／目的を達成できず」のいずれかとし、役立った場面を短文で添える。作者への質問が必要だった箇所は、成果物の説明や動作を改善して再試用する。配布しただけのものと、他者が使えたものを分けて報告する。共有範囲で許可されたデータと利用環境を前提にする。

使い方の説明、利用環境の準備、仕組みからの確認質問があることは問題ではない。それらが利用者に明示され、作者個人が補わなくても目的を達成できることを確かめる。OSSへの公開、特定の実装方式、用途を問わない汎用性は提出条件にしない。

## 最終共有会と人気投票

| 段階 | 運営案 |
|---|---|
| 発表 | Teams会議で目的・使い方・変わったことを共有する |
| 試用 | 共有会後に1週間の試用期間を設ける。各成果物へ主催者が少なくとも一人の他者を割り当てる |
| 機会の確保 | 各参加者は自分以外の2作品を試す案とする。主催者が用途と環境を確認して割り当て、偏りを抑える |
| 投票 | 使った作品のうち「自分の仕事でも使いたい」ものへ1人1票を投じ、理由を添える。自作品への投票は行わない |
| 選べない場合 | 該当なし・未試用を選べる。無理に1票を求めない |
| 表彰 | 得票数が最多の作品を人気作品として表彰する。同数なら同時受賞とする |
| 結果表示 | 得票数と、その作品を試した人数を並べる。人気投票であることを明示する |

全作品を全員が試した比較にはならないため、票数を品質や汎用性の客観順位として扱わない。表彰されなかった成果物も、試用結果と改善内容を残す。

## 部長向け報告の構成

| 報告すること | 集計・提示の方法 |
|---|---|
| 回答状況 | 各時点の回答者数／対象者数と、比較できた人数を示す |
| 実務での利用 | F1の各段階の人数分布と、同じ人の事前→中間→終了時の移動を示す |
| 自力でできる範囲 | C項目ごとに向上・同段階・低下の人数を示す。必要に応じて中央値も添える |
| 職種別の活用 | P／D項目ごとに段階3・4の人数／当該業務の回答者数を示す。PM・PLと開発者の点数を混ぜない |
| 実際にできたこと | 本人の説明に、出力や実行・試用記録を添える。未確認の説明は自己申告と表示する |
| 成果物 | 提出数、試用された数、他者が作者の補足なしで目的を達成できた数、対象業務と限界を示す |
| 表彰 | 投票結果と利用者の感想を示す |
| 今後の支援 | N項目の変化と、未解決の困りごとから教材・相談の改善を決める |

比較には同じIDで回答した人を用いる。事前と終了時の比較、中間を含む推移では、それぞれ比較対象人数を明示する。未回答・対象外は補完せず、対応する分母から除く。職種が変わった人の職種別項目は同じ業務か確認し、比較できないものを分ける。

CとBとF1は意味の異なる段階なので合算しない。0〜4を等間隔とみなした「能力が何％伸びた」という表現もしない。少人数のため、割合だけでなく人数を必ず示す。

この設計で示すのは、期間中の変化と実例である。業務経験やツール更新の影響もあり、変化のすべてを研修だけの効果とは断定しない。学習が進んで自己評価が厳しくなる場合もあるため、点数が下がった項目は自由記述と実例を併せて読む。

## 設計の参考

CDCの [研修効果の測定](https://www.cdc.gov/training-development/php/about/evaluate-training-measuring-effectiveness.html) は、学習と職場での適用を評価対象に挙げ、終了時アンケートだけでは客観的に評価できないことを説明している。これを参考に、自己申告と他者の試用記録を組み合わせた。資料は2026-09-06に確認した。

本書の設問、段階の境界、試用期間、投票方法は今回の運営案であり、CDCが推奨する固有の設問や制度ではない。
